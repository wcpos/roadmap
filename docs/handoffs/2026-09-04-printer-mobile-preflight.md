## A. Network lane on iOS and Android

- **iOS local-network permission.** Declared: `NSLocalNetworkUsageDescription` = "WCPOS needs local network access to discover and connect to receipt printers." and `NSBonjourServices` = `_ipp._tcp`, `_ipps._tcp`, `_pdl-datastream._tcp` (`apps/main/app.config.ts:17-19,67-74`, static `ios.infoPlist` merge, no plugin). **But native discovery is not Bonjour:** it is the Epson SDK's `PrintersDiscovery` (`react-native-esc-pos-printer`, `discovery/epson-native-discovery.ts:53-86`) plus Star's `StarDeviceDiscoveryManager` (Lan/Bluetooth/BluetoothLE/Usb, `star-native-discovery.ts:38-59`). Epson's SDK discovery is a **UDP broadcast to 255.255.255.255** (ePOS SDK for Android User's Manual Rev.P, "To search printers"), and on iOS 16+ sending broadcast/multicast requires the `com.apple.developer.networking.multicast` entitlement (Apple DTS, forums thread 663875; TN3179) — **not declared** (no `ios.entitlements` in `app.config.ts`). So the `NSBonjourServices` list is irrelevant to what the app actually does, and the Epson scan on iOS is predicted to return nothing while the printer is up. The permission prompt itself fires on the **first outbound unicast TCP connect to a private IP too** (TN3179: "Making an outgoing TCP connection — Yes"), so it will appear on the first Test Print even with manual IP entry; a denial surfaces as `EHOSTUNREACH` at the socket / `NSURLErrorNotConnectedToInternet` (-1009) in URL loading (forums thread 788044). Where the merchant fixes it: Settings → Privacy & Security → Local Network → WCPOS. Remedy for discovery: apply for the multicast entitlement (Apple form, lead time) or ship manual-IP as the iOS path; Star's LAN discovery mechanism is inside the compiled SDK — observe today.
- **App Transport Security vs the self-signed certificate.** Native printing never talks HTTPS to the printer (raw socket), so ATS is moot for printing. It matters for identify-at-scan: native `postEpos` is `fetch` (`identify-probes.ts`), and RN `fetch` on iOS rejects a self-signed cert with `NSURLErrorDomain -1202` "The certificate for this server is invalid" (RN `RCTHTTPRequestHandler` implements no `didReceiveChallenge`; facebook/react-native#22060); ATS does not apply to IP literals at all (Apple archived ATS reference; thread 66417), so the absent `NSAllowsLocalNetworking`/`NSAppTransportSecurity` keys change nothing. Android `fetch` → OkHttp → `SSLHandshakeException … Trust anchor for certification path not found`; the dev/adhoc `network_security_config` only adds *user* CAs (`apps/main/plugins/with-user-ca-trust.js:27-42`), which does not cover a per-printer self-signed cert, and no build-time trust anchor can (Android security-config docs). **Prediction:** the 443/8043 ePOS probe fails on both OSes → identify never picks an ePOS lane on native (safe), but "Detected: Epson" can only come from the SDK discovery result or the name. Ours must not depend on Epson's certified-domain (`*.omnilinkcert.epson.biz`, ePOS SDK JS `connect` reference) — agreed, it is browser-only and "some TM printers".
- **Android cleartext / HTTPS.** `usesCleartextTraffic` **not set**; the generated dev/adhoc config allows cleartext only for `localhost`, `127.0.0.1`, `10.0.2.2`, `10.0.3.2` (`with-user-ca-trust.js`); production has no config at all (API 28+ default: cleartext blocked, `java.net.UnknownServiceException: CLEARTEXT communication to <host> not permitted by network security policy`). Irrelevant to the raw socket; it blocks the port-80 ePOS **probe** on Android. There is no CIDR syntax in `network_security_config`, so a merchant-configurable printer IP needs `cleartextTrafficPermitted="true"` in `base-config` (via `expo-build-properties`) if we ever want HTTP probes on Android. Self-signed HTTPS per merchant: no supported path — do not build one.
- **mDNS on mobile.** No `react-native-zeroconf`, no NSD, no `MulticastLock`; `CHANGE_WIFI_MULTICAST_STATE` and `ACCESS_WIFI_STATE` **not declared** (`app.config.ts:89-100` has INTERNET, BLUETOOTH, BLUETOOTH_ADMIN, BLUETOOTH_CONNECT, BLUETOOTH_SCAN, ACCESS_FINE/COARSE_LOCATION). Android `NsdManager` would not need them (runs out-of-process; Android local-network-permission page) but the Epson SDK's own broadcast socket might — observe on the Android tablet today. **Dated item:** Android 17 makes `ACCESS_LOCAL_NETWORK` mandatory for apps targeting 17 (TCP to a LAN address without it → **timeout**, UDP → `EPERM`); `DiscoveryRequest.FLAG_SHOW_PICKER` is the no-permission escape hatch. Not today's problem; goes on the 1.11 list.
- **Signature copy.** What the native client raises today (audit §4): no response = `TCP connection to <host>:<port> timed out` after 10 s, or the socket library's error verbatim (`ECONNREFUSED`, `EHOSTUNREACH`); success = the write callback fired (**no acknowledgement — "sent" ≠ "printed", the Spec B gap exists on native too**). Blocked by the OS = iOS `EHOSTUNREACH`/-1009 after the Local Network prompt was declined; Android 17 timeout/`EPERM`. Certificate rejected = only ever from the identify probe (-1202 / trust-anchor) and must never be shown as a print error. **None of the three has distinct copy today**; the panel copy is shared with Electron (gotcha #19).

**Competitor pages (read):** *Shopify* (m30III requirements/setup/troubleshooting): "Wi-Fi support is Android only", USB Android + POS Hub, "RED (Radio Equipment Directive) activated printers don't work currently" → turn Secure Printing off with TM Utility / Web Config / EpsonNet Config; factory reset via SW button; iOS Bluetooth reset = Forget This Device; never addresses "test print fails". *Lightspeed Restaurant K-Series* (there is no Retail K-Series): LAN only, self-test sheet for IP+MAC, static IP/DHCP reservation, same-subnet check by first three octets, "Ensure … Secure Printing … disabled". *Lightspeed Retail X-Series*: the six-step Secure Printing disable (Advanced Settings → Administrator login (password = serial) → Print → Secure Printing → Disable → OK) and the best device checklist in the field: Settings → Privacy & Security → Local Network on; Settings → Apps → <app> → Bluetooth on; Settings → Bluetooth on; printer pairing mode via the Bluetooth Status Sheet action, one-minute window. *Square*: no Epson network page (organised by connection type); "Square needs access to your local network" → Settings → Square → Local Network; static IP via `http://<ip>/webconfig` (login epson/epson); never mentions RED; "Bluetooth printers … not recommended". **Nobody documents "found but test print fails" — our gap to win.**

## B. Bluetooth

- **Epson TM-m30III on iOS = MFi ExternalAccessory.** Protocol string `com.epson.escpos` (Epson iOS SDK README; MultiSafepay/react-native-epson-epos) — **already declared** with `jp.star-m.starpro` in `UISupportedExternalAccessoryProtocols` (`app.config.ts:20-24,75-77`, static merge, no config plugin needed). The SDK wrapper links both ExternalAccessory and CoreBluetooth (`PORTTYPE_BLUETOOTH_LE` is iOS-only). Pairing: printer into pairing mode (Lightspeed X steps), then iOS Settings → Bluetooth (Epson's own wording; MFi accessories are invisible to the SDK until bonded — unverified as an Epson quote). **Release item, not today:** MFi apps need Epson's Application Information Sheet → MFI PPID in App Store review notes (epson.com/Support/wa00791).
- **Android:** `BLUETOOTH_CONNECT` + `BLUETOOTH_SCAN` declared (plus legacy + location). Epson discovery requests them at runtime (`react-native-esc-pos-printer/src/core/utils/permissions.ts`), denial = code `-2` "Permission error"; **Star discovery requests nothing** (WCPOS gap, Star README says the caller must). Direct Epson `BT:<mac>` print without a scan performs no permission request. Printer must be bonded in Android Settings first (SDK `bondedDevices`); SPP under the hood is the best understanding, unverified.
- **Netum NT-1809 is BLE** (Netum FAQ: "can not connect with the device via its built-in Bluetooth, must be connected through an application"; not MFi; no AirPrint). No library names the NT-1809; the generic-58 mm family uses service `000018F0-…` / write characteristic `00002AF1-…` first (WebBluetoothCG demo), then `FF00`/`FF02`, then `49535343-FE7D-4AE5-8FA9-9FAFD205E455` (bitbank2/Thermal_Printer); prefer write-without-response; **20-byte chunks** as the floor, MTU−3 after negotiation (`requestMTU` / `maximumWriteValueLength`). PIN `0000`/`1234`. USB VID/PID default `0x0416`/`0x5011` (Winbond "Virtual Com Port", user-settable from Netum's Setup Tools). Auto-sleep drops idle links. **App state:** `react-native-ble-plx` is installed (plugin injects the Bluetooth strings) but there is no generic BLE transport; `transport/device-adapter.ts:24-26` throws `Unsupported native printer vendor for bluetooth: generic`. → **Netum on iOS/Android is unsupported today; today's Netum native cell records that refusal copy and stops. Netum's live lane today is USB on Electron.**
- Known gotcha already on record: native Add Printer refuses Bluetooth/USB for `vendor: generic` — confirmed, exact string above.

## C. USB

- **iOS: no USB printing.** UI already omits USB on iOS (`packages/core/src/screens/main/settings/printer/dialog/connection/connection-type-segmented.tsx:27-30`). Epson confirms: iOS USB only for TM-m30II/-h/-NT and TM-m50 under MFi; the TM-m30III's USB-C to an iOS device is **network tethering**, not an accessory port (Epson spec sheet CPD-62919).
- **Android:** no WCPOS USB-host code (`uses-feature android.hardware.usb.host`, `requestPermission`, `bulkTransfer`, `device_filter` all NOT FOUND). Epson/Star go through their SDKs (`USB:` target); Epson recommends a `device_filter.xml` with `vendor-id="1208"` and warns: OK on the permission dialog → ~10 s to open the port, Cancel → 30 s timeout wait (ePOS SDK Android manual Ch.6). Never tried on a device as far as the repo records. Netum USB on Android = generic = unsupported.
- **Electron/desktop:** `apps/electron/src/main/usb-printer.ts@f8ccd4f` (`usb` 2.18.0): non-Windows enumerates **USB class 0x07 only**, claims the interface, bulk OUT, 20 s timeout; Windows = spooler RAW. **Prediction for the Netum:** VID `0x0416` PID `0x5011` is a Winbond virtual-COM-port identity, so it may enumerate as CDC/serial (class 2/10) and be filtered out → "no USB printers found" with the cable in. Remedy candidates: a VID allow-list, or a serial lane (`serialport` 13 is already an Electron dependency). Signature to capture today: `lsusb`/`system_profiler SPUSBDataType` class of the Netum vs what the app lists.
- **Browser:** WebUSB via `@point-of-sale/webusb-receipt-printer` (`hooks/use-printer-discovery.web.ts:106-121`), capability `!!navigator.usb` (Chromium desktop/Android, never iOS Safari). Secure context + transient user activation required (MDN). **Chrome 142 ships the Local Network Access permission prompt** for public-origin pages fetching LAN addresses (replaces Private Network Access), Chrome 146 removes the temporary opt-out policy, and mixed content still blocks `http://192.168.x.x` from an HTTPS page — so browser ePOS printing needs the LNA grant + HTTPS 443 with the certificate accepted once in the browser. Dated; re-check before 1.11.
