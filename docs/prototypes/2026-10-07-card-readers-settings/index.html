  • Pick a direction (A, B, C or D). My recommendation is D — readers, like printers; reasons under the board. The draft PR is built from D and re-skins to whichever you pick.
  • Forget vs Disconnect as two actions, or one? Drawn as two: Disconnect releases the SDK and keeps the reader remembered (it reconnects next sale); Forget also drops the memory. The Alexa and Apple Watch pattern. Say if one "Disconnect" that forgets is simpler.

The four directions all switch together with the strip

Recommendation: D — readers, like printers.
  • It is the page the cashier already knows: the Printers page lists printers, not printer brands. A list of readers with a provider chip reads the same way, and the empty state, the Add button and the row anatomy are the existing components.
  • Most stores have one gateway and one reader; D shows them one row. A (provider rows) shows a provider with no reader as a permanent row, B's cards are tall for a row's worth of facts, and C puts Disconnect one tap further away for the case tonight proved matters most (the stale session).
  • Tap to Pay fits D without a special case: "This iPhone" is a reader row, added from the same sheet.
  • Depth stays a tap away: the ⋮ menu carries Check for update, Copy setup report and Forget; the row never grows a key–value table. Serial, location and software version live in the row's second line and the report.
Where D is weaker: a provider whose reader is not connected is only reachable through "Connect a reader", so a cashier looking for "where is Stripe?" has to open the sheet. The sheet names the providers, so it is one tap, not a hunt.
