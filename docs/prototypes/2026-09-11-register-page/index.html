Register page — three layouts, live

One in-memory register (Front counter, UK Store). Everything in the frame works: open the register, move cash, count, close, print. The strip changes who is looking and on what. The layouts differ only in the page body; the sheets, the count screen and the Reports page are shared, because those are forms and the question is the page.

What to react to

  • Layout A · Board — status card, figures, action row, movements beside tenders. The manager's view of the drawer.
  • Layout B · Ledger — the session as one running ledger with the arithmetic on show (float + cash sales − refunds + in − out = expected), actions pinned to the bottom. The cashier who is £2 short sees which line moved.
  • Layout C · Focus — one number, one button, three small ones; everything else folds. Phone-first, and the closest to what a cashier does twice a day.
  • Menu position — toggle "after POS" vs "before Reports". The icon is a drawer, since POS already owns the cash register glyph.
  • Blind count — untick view reports: the expected figure, the X-report and the variance vanish from the page and the count screen.
  • Offline close — set Network to Offline: the count screen says how many sales are not on the server yet, the closure is marked Unsynced, and the Reports detail shows the till's expected beside the server's.
  • Reports split — switch Page to Reports: the range report is renamed Sales, a Closures tab (Pro) lists every register's closures and opens one as recorded with its corrections and settled figures.
