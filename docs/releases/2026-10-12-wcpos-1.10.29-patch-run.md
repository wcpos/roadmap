## Behavior changes carried into production

- **free #2164 + monorepo #2461 (web via bundle v1.10.39 + plugin 1.10.26, desktop via electron 1.10.32, native via OTA):** a merchant's explicitly stored per-gateway POS Order Status is the settled outcome. The received page emits for a POS order at that status; the gateway catalog exposes it as `settled_order_status`; the webview's message handler and fallback poll honour it for the gateway it was stored for only. `failed`, `cancelled`, `refunded`, `checkout-draft`, `pos-open`, `pos-partial` never settle. Side effect: On hold bank-transfer/cheque sales emit from the received page again instead of waiting for the one-second poll.
- **free #2163 (every bacs/cheque/cod POS order landing on an unpaid configured status):** no `date_paid`; such orders no longer book as revenue in Analytics on the day of the sale. Known residual, fixed in #2172 for the next train: a third-party save between the status filter and the gateway's status write released the suppression early.
- **monorepo #2445 + #2449:** the server-error quoter strips only real HTML tags.
- **free #2167:** scoped Sentry PHP SDK 4.33.2.

### Notes worth keeping

- **jsDelivr's `@major.minor` range lags a fresh tag by a minute or two even after a purge.** On this train the `@1.10.39` entry asset was 200 at the first probe while `@1.10` kept reading 1.10.38 through four finished purges; a fifth purge ~90 s later flipped it. Poll the range header, don't re-tag or rebuild.
- **The bundle's entry asset lives at `build/_expo/static/js/web/<entry>.js`** (`metadata.json` → `fileMetadata.web.bundle`), not at `build/<entry>.js` — a 404 on the short path is the wrong path, not a missing build.
- **A macOS x64 notarization staple can fail on Apple's CloudKit side** (`NSURLErrorDomain -1005`, Error 68) with the arm64 job green in the same run. `gh run rerun --failed` re-runs only that job; Forge appends to the same draft.
- **Three review findings on the free sync were `main` findings again** (same pattern as the 10-08 train): the `date_paid` suppression's early release (Codex P2, real, narrow), the missing `_HPOS` twin for the new received tests (Greptile, per `.ai/rules/hpos-order-meta.mdc`), and a stale Packagist lookup on `woocommerce-stubs` 11.2.0 (CodeRabbit, dismissed — main's matrix installed it). The fourth, Codex P1 "apply the settled status to the contract-1.2 submit path", is a `next`-lane product question (on `next` a non-paid gateway result is a designed `sent` / awaiting-customer outcome with its own cancel path, not a hang) — put to Paul, not changed in the sync.
