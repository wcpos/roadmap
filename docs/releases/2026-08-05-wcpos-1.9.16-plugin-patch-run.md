## The bug

Reported by a user on 1.9.x (reproduced on demo.wcpos.com): the POS product grid showed an
outdated price/price range for variable products while the selected-variation price and the
charged amount were correct; deleting local data and re-syncing did not help.

The May recompute fix (`wcpos_get_variable_product_price_ranges`) correctly recalculated the
range on every response, but injected it via `$product->update_meta_data()` (writes to
`WC_Meta_Data::$current_data`) while `wcpos_parse_meta_data()` serialized each meta via
`WC_Meta_Data::get_data()` (returns the **original DB-loaded** data). So for any product whose
`_woocommerce_pos_variable_prices` row was already persisted in `wp_postmeta`, the stale stored
value was served forever and the recompute was discarded.

**Fix** (free commit `9c998a98`, PR #1436): serialize `key`/`value` through the `WC_Meta_Data`
magic getters (current_data), keeping the plain-array output shape and emitting `id` only when
present before. Covers products (grid + single) and variations; orders/coupons share the trait
and only benefit. Server-side only — no client/js-bundle change needed. Regression test included
(fails without the fix).
