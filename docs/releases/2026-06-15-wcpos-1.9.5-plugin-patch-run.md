# WCPOS Release Run Reference — 2026-06-15 (1.9.5 plugin-only patch)

A **plugin-only patch** release of the free and pro PHP plugins (no monorepo / web-bundle /
electron / mobile this cycle). It shipped a single customer-facing fix plus CI/translation
maintenance, and it **corrected a wrong runbook lesson** from the 2026-06-13 (1.9.4) run
about how the plugin `release.yml` workflows publish.

## What shipped

- **Free — payment-gateways endpoint fatal fix** ([#1161](https://github.com/wcpos/woocommerce-pos/pull/1161)):
  `GET /wcpos/v1/payment-gateways` returned a fatal 500 on stores running certain
  third-party gateways (reported with ToyyibPay) that only register their settings under
  `is_admin()`. The catalog controller used to extend
  `WC_REST_Payment_Gateways_Controller` and call `parent::prepare_item_for_response()`,
  forcing every gateway's `init_form_fields()` to run in a non-admin REST context. Reshaped
  `Payment_Gateways` to extend `WC_REST_Controller`, declare its own schema, and build each
  payload from public properties + the POS `Gateway_Contract` — it never calls
  `get_settings()`/`init_form_fields()`.
- **Free — CI/maintenance**: standalone-Composer install for the POT update workflow
  ([#1156](https://github.com/wcpos/woocommerce-pos/pull/1156),
  [#1162](https://github.com/wcpos/woocommerce-pos/pull/1162)); php-cs-fixer dev-dep bump
  ([#1153](https://github.com/wcpos/woocommerce-pos/pull/1153)).
- **Pro — no Pro-specific product code**. Pro bundles the free plugin via Composer at build
  time (`vendor/wcpos/woocommerce-pos`), so the 1.9.5 rebuild is what ships the gateway fix
  to Pro users. Also POT/CI fixes and a php-cs-fixer bump.

## Corrected lesson — the two plugin `release.yml` workflows are NOT the same

The 2026-06-13 (1.9.4) reference claimed "both plugins auto-release **and** auto-publish on
merge; the free WP.org deploy happens automatically." **That was wrong.** What actually
happens:

- **Free `release.yml`** creates the GitHub release as a **DRAFT** (`draft: true`), builds +
  uploads `woocommerce-pos.zip`, and opens a CodeRabbit "Generate release notes" issue. There
  is **no publish step** — it stops at the draft. You must **manually publish** the draft
  (`gh release edit vX.Y.Z --draft=false --latest`) after curating notes. Publishing is what
  fires `wporg-deploy.yml`. So for the free plugin, **merge ≠ live**.
  - Re-reading the 1.9.4 release confirms this: it was created as a draft at `11:51` and
    `publishedAt` was `11:56`, with the WP.org deploy starting 2s later — i.e. it was
    published by hand during that run, not automatically. The 1.9.4 note mis-recorded it.
- **Pro `release.yml`** *does* have a `🚀 Publish Release` step, so merging the bump PR
  **auto-publishes** immediately. Pro has no WP.org deploy (distributed via the Pro update
  server), so auto-publish is fine.
- **Order still matters:** merge **free first** so its tag exists (the draft-create step tags
  it), then **pro** — pro's Composer build pulls the free plugin, so the free tag must exist
  when pro builds. Free only needs to be *tagged*, not *published*, before pro merges.

## Other notes

- **WP.org propagation lag.** After publishing free, `api.wordpress.org/.../woocommerce-pos.json`
  and `downloads.wordpress.org/plugin/woocommerce-pos.<ver>.zip` lagged the SVN commit
  noticeably this run (still showing `1.9.4` / 404 several minutes after a successful deploy;
  the 1.9.4 run propagated in ~3 min). **SVN is the source of truth** — verify
  `plugins.svn.wordpress.org/woocommerce-pos/trunk/readme.txt` Stable tag and `tags/<ver>/`
  rather than trusting the lagging API/zip.
- **`update-pot.yml` still noisy.** The automated POT-update bot opens a follow-up PR on each
  push (e.g. free #1164); non-blocking.
- **Do NOT dispatch `manual-release.yml`** for the plugins — it races `release.yml`.
