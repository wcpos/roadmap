## What rides

Monorepo `v1.10.14...main`: #2051 only — `useGuardedExtension` refused to extend a full read once the search lane read `exhausted`, so a search with more hits than the screen's page size but fewer than one wire page stuck at the first page (Products page showed 10 of 13 for a term the POS panel showed 13 of; frikifunko, 1.10.14). Since #1935 the walk over-fetches a dial-sized page and persists every row, so a complete lane can hold more rows than the limit; the guard now ends paging only on a short read.

Plugin legs skipped on the partial-lane rule (roadmap release reference, "Web bundle hotfix": `web_bundle` + `monorepo`): the fix is app code served by the `@1.10` bundle ref, the plugin carries no change, and the worker is byte-identical.

## Release notes (app v1.10.15)

- **Product search shows every match again.** When a search matched more products than fit on the first page, the Products page stopped at that page and scrolling to the end loaded nothing more, so the same search could show fewer results there than in the POS products panel. Every searchable list pages the same way and is covered by the fix.

### Notes worth keeping

- **A search fix can be inert for the latency seam and still fail it.** `search-latency.spec.ts` (first row 3.5–4.1 s vs a 3 s ceiling) went red on a runner that also logged cache-service 400s; the spec's stub serves a full page so `exhausted` stays `false`, the one input #2051 does not touch. Passed on rerun with no code change. Read the spec's inputs against the diff before treating a ceiling breach as the change's.
- **A sync merge is a review of both lanes.** Resolving #2053 exposed a live 1.10.14 defect nobody had reported (the divergence rebuild no-op), found only because the two lanes' independent fixes to the same file were laid side by side. #2054 is the backport; whether it cuts a 1.10.16 is Paul's call.
- **Release branches were cut through the git-data API, no local tree**: branch ref → blob → tree → commit → ref → PR. Same result as the worktree recipe, and it sidesteps the `apps/web` gitlink dance entirely.
- **`gh pr merge` after `gh pr ready` refused once** ("base branch policy prohibits the merge") — the known transient; `--auto` queued it and it merged when the ready-flip CI landed. The phone native jobs on a package.json bump are cancelled by `cancel-native-runs`; only ✅ Merge Gate is required.
- **`@1.10` lagged the tag by ~40 s this time** (three stale reads), a single purge of `metadata.json` + `index.html` flipped it. Read before purging, purge only the range, never the fresh exact tag.
