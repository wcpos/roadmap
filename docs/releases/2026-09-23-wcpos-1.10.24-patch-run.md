## Things that cost time, or nearly did

- **Pro's release looked zip-less and wasn't.** `gh release view v1.10.20 --json assets` and the release object's embedded `assets` both returned empty after `manual-release.yml` went green, which reads exactly like a failed upload on a published release. The assets endpoint (`/releases/<id>/assets`) showed `woocommerce-pos-pro.zip` `state=uploaded`, updated 09:59:48 — before the publish step. The release object's asset list was lagging. **Check `/releases/<id>/assets` before re-drafting or re-dispatching.** Nearly flipped a live Pro release back to draft over it.
- **A release's `created_at` is its commit's date, not when the release was made.** Pro's showed 09:08 (the merge) for a release created at 09:57, which briefly looked like a second workflow had cut it.
- **Electron's `release-notes` mirror copies the app body verbatim, including the phone OTA paragraph.** Removed it by hand on the desktop draft before publishing (with `tag_name` explicit).
- jsDelivr kept resolving `@1.10` to 1.10.33 for a minute after the tag and first purge; a second purge fixed it.
