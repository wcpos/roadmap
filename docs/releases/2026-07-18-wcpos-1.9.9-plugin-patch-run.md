# WCPOS Release Run Reference — 2026-07-18 (1.9.9 plugin-only patch)

A **plugin-only patch** release of the free and Pro PHP plugins (no monorepo / web-bundle /
electron / mobile this cycle). It shipped an **important security fix** (path-traversal in
virtual template resolution) plus a mixed-content payment-link fix and translation/CI
maintenance.

## Release Versions

| Component | Repo | Previous | Released |
| --- | --- | ---: | ---: |
| Free WordPress plugin | `wcpos/woocommerce-pos` | `v1.9.8`* | `v1.9.9` |
| Pro WordPress plugin | `wcpos/woocommerce-pos-pro` | `v1.9.8` | `v1.9.9` |

\* Version numbering only. **The free `v1.9.8` GitHub release was never published** — its draft
was created on merge but never promoted, so no `v1.9.8` git tag exists and WordPress.org stayed
on **1.9.7** the whole time. So on WP.org the free plugin went **1.9.7 → 1.9.9** directly. The
1.9.9 `readme.txt` carries **both** the 1.9.8 and 1.9.9 changelog entries, and the 1.9.9 build
includes the 1.9.8 code (it was already on `main`), so users updating from 1.9.7 receive
everything. The stale `v1.9.8` **draft** was left in place (harmless; not deleted).

No app / monorepo / web-bundle / electron / mobile changes this cycle.

## What shipped

- **Security — virtual template path traversal** ([free #1265](https://github.com/wcpos/woocommerce-pos/pull/1265)):
  the templates REST endpoint (`GET /wcpos/v1/templates/<id>`) accepted an unvalidated `type`
  query param that flowed into `Templates::get_virtual_template_path()` as `"$type.php"`,
  allowing `../` traversal to resolve arbitrary files. Fix adds an `enum` +
  `sanitize_key`/`rest_validate_request_arg` on the `type` REST arg (rejects with HTTP 400), a
  `SUPPORTED_TYPES` guard in `get_virtual_template_path()`, and a `realpath()` containment
  check that confirms the resolved path stays inside the trusted template directory (also
  blocks symlink escape). Tests added for all three.
- **Bug — trailing-slash POS URLs** ([free #1264](https://github.com/wcpos/woocommerce-pos/pull/1264)):
  POS checkout/receipt/auth URLs were always slash-less, so origin rewrite rules that force a
  trailing slash could 302 them to a hardcoded `http://` target and get blocked as mixed
  content (real merchant failure, July 2026). `user_trailingslashit()` now applied to the path
  portion in `wcpos_url()`, `wcpos_checkout_url()`, and `Template_Router::get_auth_url()`.
- **Free — maintenance**: `.pot` refresh; test-matrix + `wp-phpunit` bump.
- **Pro — Pro-only**: Pro update icon points at the hosted CDN asset
  ([pro #365](https://github.com/wcpos/woocommerce-pos-pro/pull/365)); test-matrix bump. Pro
  bundles free via Composer (`dev-main`), so the security + URL fixes reach Pro users through
  the rebuild.

## Flow performed (with artifacts)

1. **Local `main` was stale** in both plugin clones — the security fix and URL fix were already
   merged upstream. Fast-forwarded both to `origin/main` before branching.
2. **Free bump PR** — `1.9.8 → 1.9.9` in `woocommerce-pos.php` (header + `VERSION`),
   `package.json`, `readme.txt` (Stable tag + changelog) — [free #1268](https://github.com/wcpos/woocommerce-pos/pull/1268).
   Full CI green (Merge Gate + PHP matrix), merged to `main`.
3. **Pro bump PR** — `1.9.8 → 1.9.9` in `woocommerce-pos-pro.php` (header + `VERSION`),
   `package.json`, `CHANGELOG`, `CHANGELOG.md` — [pro #366](https://github.com/wcpos/woocommerce-pos-pro/pull/366).
   Merged after free (Composer `dev-main` ordering).
4. **Free release published** — `release.yml` created the draft on merge; published manually
   with curated notes (`gh release edit v1.9.9 --draft=false --latest`) →
   [free v1.9.9](https://github.com/wcpos/woocommerce-pos/releases/tag/v1.9.9). Fired
   `wporg-deploy.yml`; **WP.org SVN `Stable tag: 1.9.9`** and `tags/1.9.9/` = HTTP 200 confirmed
   (~2 min).
5. **Pro release published** — `release.yml` auto-published on merge →
   [pro v1.9.9](https://github.com/wcpos/woocommerce-pos-pro/releases/tag/v1.9.9). Its
   auto-generated body (Pro PRs only) was **overwritten** to mirror the free user-facing notes +
   the Pro-only icon fix, per [[pro-release-notes-mirror-free]] (bare `#refs` dropped).
6. Release worktrees removed; merged worktrees cleaned up.

## Lessons / gotchas

- **Free `v1.9.8` was merged-but-never-published** — a live example of the free-plugin
  manual-publish gap in [[wcpos-plugin-release-automation]]. Publishing a later version with a
  cumulative `readme.txt` changelog recovers cleanly (WP.org went 1.9.7 → 1.9.9). **Check
  `gh release list` for stale drafts and compare against WP.org SVN stable tag before assuming
  the last version shipped.**
- **Pro Merge Gate re-ran** between the first blocked merge attempt and the successful one —
  the required `✅ Merge Gate` check briefly re-entered `IN_PROGRESS`, showing `BLOCKED`. Waited
  for it to return to `SUCCESS`; only the (non-required) PHP matrix was still running at merge
  time (`UNSTABLE`), which the ruleset permits.
- Process otherwise matched [[wcpos-plugin-release-automation]]: free = draft → manual publish →
  WP.org; Pro = auto-publish → overwrite body.
