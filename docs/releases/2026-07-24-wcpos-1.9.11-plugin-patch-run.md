# WCPOS Release Run Reference — 2026-07-24 (1.9.11 plugin-only patch)

A **plugin-only patch** release of the free and Pro PHP plugins (no monorepo / web-bundle /
electron / mobile this cycle). The notable event of this run was **picking up a paused release**:
another agent had opened the bump PRs, then ~30 more free-plugin commits landed on `main` (a big
Cloud Print push plus i18n chores). Both release branches had gone stale/`CONFLICTING`, and the
paused agent's curated changelog was **factually wrong** for what had since shipped — the Cloud
Print relay went from *opt-in* to *on-by-default* and a whole print-queue feature landed after the
notes were written. Both branches were rebuilt on current `main` and the notes re-curated.

## What shipped

All user-facing changes are free-plugin changes; Pro carries them via the Composer bundle.

- **WCPOS Cloud Print relay** — routes Star CloudPRNT / Epson Server Direct Print polling through
  `cloudprint.wcpos.com` when a store's hosting or firewall blocks the printer's direct
  connection; jobs start on the printer's next poll instead of the next heartbeat, and printer
  cards surface a blocked-origin warning. **On by default** with a code-level opt-out (changed from
  opt-in in free `bbaacf2c`, after the paused agent's original notes were written). Receipt
  contents transit the relay when it is used — disclosed in the changelog + privacy FAQ.
- **Cloud Print queue** — live print-job queue on the Cloud Print settings screen (status, retry,
  clear); completed payloads stripped and old jobs purged automatically.
- **Storefront receipts** — customers download their order receipt as a PDF (WCPOS template) via a
  Receipt button on My Account → Orders; `[wcpos_receipt]` shortcode for order-received / custom
  pages.
- **Poll-URL path credentials** — printer credentials moved into the URL path so firmware that
  URL-encodes the query string (eg: Star TSP100IV) can authenticate; existing configured URLs keep
  working.
- **WCPOS Pro license image** — the Pro panel image now loads correctly.

Plus `.pot` refreshes and translation version `2026.7.6` in both plugins.

## Picking up the paused release — what was stale

The prior agent left free [#1319](https://github.com/wcpos/woocommerce-pos/pull/1319) and Pro
[#385](https://github.com/wcpos/woocommerce-pos-pro/pull/385) open, nothing merged. Between the
bump PRs being cut and this pickup:

- **~30 commits landed on free `main`** (Cloud Print relay/queue/retention, storefront receipts,
  path-credential poll URLs, Pro license image fix, `.pot` + translation `2026.7.3 → 2026.7.6`,
  CI merge-gate hardening). Both bump branches were behind → GitHub reported them `CONFLICTING`.
- **The curated changelog was factually stale.** It described the relay as "opt-in from the Cloud
  Print settings"; free `bbaacf2c` had since made it **on-by-default with a code opt-out**, and the
  print-queue feature wasn't mentioned at all. Shipping those notes would have misdescribed a
  privacy-relevant default to merchants.

**Fix:** reset each release branch to `origin/main`, re-applied the version bumps, and re-wrote the
changelog against **all** commits since `v1.9.10` (not just what existed when the PR was cut).
Force-updated both existing PRs so the numbers/URLs were preserved.

## The Composer pin — repointed cleanly this time

Pro's release workflows pin free to an exact commit (see the 1.9.10 run doc for the full
gotcha). Both `.github/workflows/release.yml:72` and `manual-release.yml:48` were repointed
`dev-main#367cf158` (free's 1.9.10 merge) → **`dev-main#f386ba7c`** (free's 1.9.11 `main` tip) as
part of the Pro bump commit, so there was no near-miss this run. Verified post-publish: the shipped
`woocommerce-pos-pro.zip` bundles `vendor/wcpos/woocommerce-pos` at `Version: 1.9.11`.

**Follow-up still open:** drop the pin (let `dev-main` float) or derive it in-workflow from free's
`main` tip, so it can't silently rot.
