# Part 1 — What to test

Ordered by risk. The first four sections are where a bad 1.10.0 would hurt.

## 1. The 1.9 → 1.10 upgrade path ⚠️ highest risk

This release replaces the data layer. Every existing install rebuilds local storage on first launch.

- [ ] **Upgrade an existing 1.9.17 install with real local data** (not a fresh profile). `purgeLegacyDatabases`
      had zero callers until mono#1004; the product schema was bumped to v1 (mono#1337) after an in-place
      edit bricked existing scope databases on `next`; the FlexSearch index was version-bumped to `v2` to
      force a re-tokenize (mono#754). All three fire on the same first boot.
- [ ] **Native upgrade specifically** — storage moved from expo-sqlite to the expo-filesystem OPFS engine
      (mono#782). Different code path from web/Electron.
- [ ] **Electron upgrade** — the Node stack was retired from the main process (electron#353), image cache
      and updater moved to Chromium `net.fetch`.
- [ ] Confirm "Clear All Local Data" actually clears (mono#814 — it was missing `pos_v*` scope databases,
      i.e. a silent no-op) and that native does it safely (mono#1342: schedule, reload, or freeze).
- [ ] Sanity-check the **plugin** upgrade: activator schema latch holds until the upgrade fully succeeds
      (free#1414), role capabilities re-sync when the definition changes, not only on a version bump
      (free#1590).

## 2. Sync correctness end-to-end ⚠️

The whole engine is new (`@wcpos/sync-core` + `@wcpos/sync-engine`, ported mono#632) against a brand-new
server API (`wcpos/v2`). The sync-API feature gate was removed entirely in free#1606 — v2 routes now
always register, so there is no fallback path.

- [ ] **Fresh-profile initial sync on a large store.** The 1.10 blockers were all here: products stalling
      at partial catalog (mono#894, #850), customers shortfalling forever (free#1378).
- [ ] **The catalogue is complete.** Compare POS totals against WooCommerce admin counts for products,
      variations, customers, orders, coupons. The census is supposed to give honest denominators now.
- [ ] **Scroll past the old walls.** Products used to dead-end at 1,000 rows and orders at 200 — silently
      (mono#1030). Scroll a long way in both, and in Customers.
- [ ] **Sorting and filtering.** POS product default sort changed to **name ascending** (mono#1376,
      was `menu_order, id`). Sort by SKU / stock quantity — these used to silently fall back (mono#947).
      Filter orders by cashier, store, customer, date range.
- [ ] **Search.** Mid-word/compound match (`saippua` → `Kuorintasaippua`), multi-word customer search
      (`John Smith`), variation search by SKU and name. Once the catalogue is local, POS search should
      issue **zero** server requests (mono#979).
- [ ] **Deletes propagate.** Delete a product / customer / coupon server-side, confirm it leaves the POS
      (tombstones + manifest pruning, mono#1287).
- [ ] **Conflict + retry.** Edit the same order from POS and WP Admin. A write conflict should auto-recover
      once and surface if it can't (mono#1212, #1475).

## 3. Money and tax ⚠️

Several precision bugs were fixed at the wire level. Any regression here is a real-money bug.

- [ ] **Six-decimal precision round-trip.** Orders pulled from the server were arriving rounded to display
      decimals (mono#946 / free#1466). Save an order with awkward line prices, reload it, compare totals.
- [ ] **Compound taxes.** Sequencing now follows `tax_rate_priority` (mono#1120); rounding matches
      WooCommerce cents-precision (mono#1123); `tax_lines` mirror Woo's storage precision under
      round-at-subtotal (mono#1117). Test a store with compound + multiple priorities.
- [ ] **Negative fees / discounts as fee lines** — tax semantics now gate on the order, not the request
      (free#1503).
- [ ] **Multi-currency and multi-store.** Cash change and card cashback render in the *order's* currency,
      not the site default (free#1586, free#1434). Multi-store orders must not get site-base taxes
      (free#1545).
- [ ] **Refunds** (promoted to a v2 online-only service, pro#362) — full and partial, and the refund
      value math (mono#1343).
- [ ] Watch for the **money divergence alert** at save time (mono#1033) — it should not fire on healthy saves.
- [ ] Receipts print the **currency symbol**, not the ISO code (mono#1484).

## 4. Offline & degraded connectivity ⚠️ (roadmap epic #41)

- [ ] **Work offline, come back.** Build and save orders offline, edit customers/coupons/stock (Pro),
      queue **receipt emails** (mono#1021, #165). Reconnect, confirm all replay and none duplicate.
      Note: **taking payment still needs a connection** in 1.10 — checkout renders a server-hosted
      payment page. Offline checkout (cash first) is 1.11 work, so don't test for it here.
- [ ] **Kill the server mid-sale.** Online dot honesty + manual sync spinner/toast (mono#1135).
- [ ] **Dead-letter recovery.** Force a rejection (e.g. invalid data), then use the recovery panel to
      inspect the reason and requeue (mono#1011, #1016). Discard should remove born-local ghosts.
- [ ] **Degraded storage blocks checkout** rather than losing the sale (mono#1019) — with a reload CTA.
      Barcode scans should fail *loudly* in this state (mono#1010), which is the #163 failure mode.
- [ ] **Crash screen "Try again" must not wipe unsent sales** (mono#1203).
- [ ] **Multi-tab (web).** Cross-tab leader election landed (mono#1057). Open two tabs, sell in both,
      confirm one writer and no phantom orders (mono#1061).
- [ ] **Store switching** mid-session — transactional hydrate-then-commit (mono#882).

## 5. Overselling prevention (roadmap epic #1)

Default **off** — enable the toggle first (Settings → Checkout).

- [ ] Cart blocks adding beyond available stock, with the quantity shown (mono#42, #724).
- [ ] Variations popover shows per-variation stock; out-of-stock variations hide per the display setting
      (mono#719, #721).
- [ ] **Server-side safety net.** With the setting on, a checkout exceeding stock must be rejected with
      `wcpos_insufficient_stock` (HTTP 400) listing every failing line (free#1259 / free#443).
- [ ] Backorders `allow`/`notify` must **never** block. Unmanaged items with a manual `outofstock`
      status **must** block. Variation stock aggregates to the parent when the parent owns stock.
- [ ] Draft/cart syncs always succeed — only checkout is gated.
- [ ] Missing `backorders` field sells out at zero, matching WooCommerce (mono#1403).
- [ ] Stock badge derives status locally rather than waiting for the server echo (mono#1380).

## 6. Barcode scanning (largely new)

- [ ] **Camera scanning** — inline panel below the filters, resizable drag handle. Web, Electron, iOS,
      Android (mono#737, #913, #1130).
- [ ] **Keyboard-wedge scanners** — now require a scanner-like burst to register (mono#745), so test that
      normal fast typing doesn't trigger and a real scanner does.
- [ ] **Serial / HID-POS** — Web Serial + WebHID (mono#743), Electron device chooser (mono#748),
      manual vendor RFCOMM service-UUID entry (mono#1452).
- [ ] **Bluetooth SPP** connect + keyboard-mode explainer (mono#1257); **iOS BLE** via vendor GATT,
      tested against Netum (mono#1465).
- [ ] **Android** attributed wedge — native key interceptor (mono#734).
- [ ] **UPC-A ↔ EAN-13**: scanning a UPC-A should resolve to the digits printed on the package
      (mono#747, #1485). This changed twice — worth a careful pass.
- [ ] **Barcode field** now defaults to `_global_unique_id` (GTIN) (free#1255). `_sku` and
      `_global_unique_id` are always selectable (free#1602); custom `meta_data:<key>` mappings are
      advertised (free#1390). Changing the field re-digests the catalogue (free#1653) — confirm the
      catalogue actually rebuilds.
- [ ] **Scan sounds** + themes, quieter too-short warning (mono#744, #1278).
- [ ] **Barcode test panel** — timing chart, verdicts, one-tap fixes (mono#728) and the Scanner Setup Wizard.
- [ ] Scans go to the search field on the Orders screen (mono#1448); scans are gated on screen focus
      (mono#1436); repeat scans racing the skeleton insert reuse the open order (mono#920).
- [ ] **Online fallback with auto-add** (free#465) — scan something not in the local catalogue.

## 7. Store Health (new screens)

- [ ] **Database tab** — real storage numbers, variations total, server totals, clock-skew warning,
      per-row "Check for changes now".
- [ ] **Performance tab** — measured actuals, live tuning dials, trend charts.
- [ ] **Logs** — flat ledger with TOOK/STATUS columns, level pills, whole-row expand, infinite scroll,
      per-event descriptions, copyable error codes, and Learn-more deep links into the docs site.
      Every sync warn/error row should carry a registry error code.
- [ ] Confirm the **error-code docs links actually resolve** on the live docs site (mono#1169 emits MDX
      from the registry with a lockstep gate — but verify the published side).
- [ ] Health page should show a stale total rather than going blank when a census expires (mono#1379),
      and must not mark sold orders "stuck" for a money divergence (mono#1041).

## 8. Printing & receipts

- [ ] **Star CloudPRNT** — real `mediaTypes` negotiation with a `text/plain` fallback (free#1671), and
      **server-rendered PNG receipts** for printers that can't decode StarPRNT (free#1685, mono#1506).
- [ ] The non-functional StarPRNT **fixed-layout adapter was deleted** (free#1588) — anyone on it needs
      a different template.
- [ ] **Print triggers per rule** — print on order created vs. once paid (free#1525); multiple copies
      per rule (free#1424).
- [ ] **Print queue**: a retried failure used to stay in "Needs attention" and be retried again
      (free#1362 / free#1592).
- [ ] **Thermal**: mbstring fallback, wider Star width table, shared text layout (free#1674); out-of-range
      attributes clamp identically in preview and print (free#1678).
- [ ] **Offline receipts render in the right language** — the store payload now ships a `receipt_i18n`
      label dictionary which is persisted for offline renders (free#1651, mono#1464).
- [ ] Templates are labelled **"Thermal"**, not "ESC/POS" (mono#825).
- [ ] Local fallback render must not auto-print (mono#1253).

## 9. Access control & capabilities ⚠️ behaviour change

- [ ] **Default cashier capabilities now include catalog create + edit** (free#1541). Deletes stay opt-in.
      Verify against an existing site's cashier role after upgrade.
- [ ] **Catalog and coupon writes via v2 require real WP capabilities** (free#1501). A cashier without
      them should get a clear rejection with the server's reason, and the local edit should auto-revert
      (mono#1091).
- [ ] **Task-grouped capability toggles** on the Access screen (free#1597).
- [ ] Catalog editability in the app is gated on the user's real server capabilities (mono#1094), and
      login must still work against servers that don't send a capability payload (mono#1113).

## 10. Platform & environment

- [ ] **Expo SDK 57 / React Native 0.86** (mono#785) — a full native regression pass.
- [ ] **iPad**: dropdowns not opening was app-wide on iPadOS (mono#863 / #1206). Test every Select.
- [ ] **Electron 43, TypeScript 6** (mono#348) and the Node-stack retirement (electron#352, #353).
- [ ] **Language switching** — one i18next instance so a change reaches every consumer (mono#1199 / #40),
      settings form labels re-render, and the stuck-record headline no longer falls back to English
      (mono#1511).
- [ ] **Standalone / non-WP-hosted clients** — the B-series work (B4–B10) added query-param JWT,
      `?rest_route=` transport, a header echo probe, and a response-body envelope for hosts that strip
      headers. Worth testing against a hostile host (Cloudflare bot challenge, security plugin, etc.).
- [ ] REST routes now register without the `X-WCPOS` header (free#1467 / free#1075) and match
      case-insensitively (free#1487).

## 11. Settings & UI

- [ ] **Settings redesign** — row-based layout, short nav labels, the shortcuts page is gone (mono#771).
- [ ] **Settings and Store Health are drawer areas now — the modal is retired** (mono#700).
- [ ] Shipping tax class round-trips correctly (mono#1498, #1503 — merchant-defined classes were rejected).
- [ ] Column changes apply immediately to variable/variation rows (mono#1230).
- [ ] Edit modals close after a successful save (mono#1215).

# Part 2 — User-facing changelog

Moved to its own file: **`2026-08-23-wcpos-1.10.0-release-notes.md`**, which carries three versions —
complete notes for GitHub, a tighter marketing entry for WordPress.org `readme.txt`, and a short
heads-up post for Discord.

Framing that drove all three: 1.10 is **the sync release**. Everything a merchant notices comes from
one change — the server keeps a change log now, so the POS asks *"what changed since I last looked?"*
instead of re-downloading the store. Speed, uncapped scrolling, honest totals, offline queuing and real
sorting all fall out of that. The invisible performance work is translated as **"the POS asks your
server for less, less often"**, which shared-hosting merchants understand immediately.

# Part 3 — Developer / breaking-change notes

Not merchant-facing, but these need to be documented somewhere third-party developers will read.

1. **The sync API namespace moved: `wcpos/v1/sync/*` → `wcpos/v2/*`.** The `sync/` prefix is gone
   entirely (free#1251). All shared POS services are `wcpos/v2` pass-throughs (free#1252); Pro mirrors
   the split (pro#357). The app consumes `wcpos/v1` nowhere (mono#710).
2. **The sync-API feature gate is gone** (free#1606) — `woocommerce_pos_sync_api_enabled` no longer
   exists and v2 routes always register. The orphaned option row is inert.
3. **Legacy `API\Settings` controller methods removed** (`get_general_settings()`,
   `update_access_settings()`, `get_general_endpoint_args()`, `remove_license_transient()`, …). The FQCN
   alias survives; the methods don't. Triaged in free#1605 and closed — **confirm the resolution was
   "documented break" and not "compat wrappers", and if it was a break, document it publicly.**
4. **Default cashier capabilities changed** — catalog create + edit added (free#1541).
5. **Catalog/coupon writes require real WP capabilities** (free#1501).
6. **`wooOrderId` retired from the order pull envelope** (free#1635 / mono#1367); identity is uuid-primary
   with an opaque string `remoteId` (mono#1254).
7. **Typed meta on the wire** — one normalizer, hashed before stamping (free#1250, mono#675). Consumers
   stop parsing, writers stop stringifying.
8. **Unified sync journal** — `sync_index` folded into `change_log`; one table, one writer, one contract
   (free#1581 / mono#1205, closes free#1560).
9. **POS line-item pricing storage is now documented** for third-party sync compatibility (free#585).
10. **New public endpoints:** `wcpos/v2/site` (discovery), `wcpos/v2/ping` (reachability),
    `wcpos/v2/echo` (header probe). Store discovery prefers `wcpos/v2/site` over the REST index.
11. **Response changes:** `X-WCPOS-Pressure` on all responses; opt-in `_wcpos` body envelope for hosts
    that strip headers; `private/no-store` + `Vary` on every WCPOS REST response.
12. **POS product default sort changed** from `menu_order, id` to `name` ascending (mono#1376).
13. **Native storage moved** from expo-sqlite to the expo-filesystem OPFS engine (mono#782); the
    `expo-sqlite` dependency is gone.
14. **StarPRNT fixed-layout output adapter deleted** (free#1588 / free#1341).
