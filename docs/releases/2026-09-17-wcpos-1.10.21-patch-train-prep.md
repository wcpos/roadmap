## Draft release body — app v1.10.21 (also the desktop body via the release-notes job)

- **A till no longer gets stuck at login on "Something went wrong: useStoreSession must be called within an active store session".** A damaged range in the till's local database made the login write fail and left the cashier on a red banner. The write is now repaired and retried, and if the saved session still cannot be honoured the till returns to the store list with a message instead of the banner. If the site has to be added again, it opens a fresh local database and does not pick up sales still waiting to sync in the old one.
- **A newly connected till no longer misses a stock change made in its first minute.** A product set out of stock on the server shortly after a new device, login or reset stayed "in stock" on the till indefinitely. The till now records the server's position before the first browse, so the change arrives with the next sync.
- **A variation whose stock is managed at product level shows the right stock in the variation picker.** When the parent product sold out, the picker's badge and Add to Cart button kept saying "in stock" for up to five minutes. They now read the parent's stock, the same way the cart does.
- **Switching stores no longer carries the previous store into the first requests of the new one.** Requests made while a switch was still completing used the outgoing store, so the first products or barcodes could belong to it until the next sync. Pro multi-store only.
- **Health > Logs records a screen error the app catches** as "Part of the screen failed to load", and reports it when you have allowed error reporting.

Phone and tablet apps on the 1.10.18 store build receive this version as an over-the-air update: it downloads in the background and applies on the next cold start after that, with no store update needed. Older store versions must first update to 1.10.18 from the App Store or Google Play.

(OTA paragraph assumes `eas fingerprint:compare` matches for both platforms. The delta is JavaScript only, so it should; confirm before dispatching.)

## Risk read

- **#2120 is low risk, corrected after checking the code.** It refuses an incomplete session at login and store switch, but the check is the same five fields the shipped 1.10.20 `useStoreSession` already throws on at every render (verified against the v1.10.20 file), applied to the same hydration output. A login that would fail the new check already fails today with the red banner; the PR only moves the failure earlier, before the broken pointer is persisted, and swaps the banner for a toast and the store list. `extraData` is created by hydration rather than looked up, so only the three database rows can be missing, which is exactly the #2112 damage case. No new failure surface.
- **#2113 prime + its nine follow-up commits** (cross-tab first-prime-wins, abort handling, lane chain) is the most iterated code in the set. Bounded: runs once per fresh scope, and a failure falls back to the old lazy prime with a warning.
- **Storage repair-and-retry** sits on every write path, but it is mirrored byte-identical from electron#460 (71 tests, mutation-checked) and already on electron `main`.
- #2116 and #2118: small, tested, low.
- Native E2E red on #2114/#2119 is the usual non-blocking lane.

## Is it worthwhile?

Yes, on the first bullet alone: real merchants are blocked at login today on desktop 1.10.22/23 with only a manual workaround, and the two stock-accuracy fixes are the kind of thing that causes overselling complaints. Desktop is the leg that matters most (the reported tills are Windows), and desktop does not follow the bundle, so a bundle-only hotfix would not reach them.
