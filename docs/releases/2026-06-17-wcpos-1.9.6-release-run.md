# WCPOS Release Run Reference — 2026-06-17 (1.9.6 full train + re-align)

A **full release train** (web bundle + app/monorepo + electron + mobile + free + pro),
conducted following the [2026-06-15 1.9.5 run](2026-06-15-wcpos-1.9.5-plugin-patch-run.md)
and [2026-06-13 1.9.4 run](2026-06-13-wcpos-1.9.4-release-run.md) references. It shipped
cash-drawer / cloud-print support and **re-aligned the version lines** that had diverged
after the 1.9.5 plugin-only patch. It also surfaced several process changes since 1.9.4.

## New lessons (runbook corrections since 1.9.4 / 1.9.5)

### Web-bundle auto-tag is DISABLED — tag the release manually
`wcpos/web-bundle`'s `tag-and-release.yml` has been renamed to **`tag-and-release.yml.old`**,
so merging the bundle PR **no longer creates the `vX.Y.Z` tag/release**. After merge, create
it by hand: `gh release create v1.9.9 --repo wcpos/web-bundle --target <merge-commit>
--title v1.9.9 --notes ...`, then purge jsDelivr (`@1.9`, `@main`). The 1.9.4 "merge
auto-releases the bundle" step is obsolete.

### Building the web bundle locally needs the RXDB Premium license
`pnpm web build` runs a full `expo export`, which needs `rxdb-premium` installed. Its
installer reads the license from `accessTokens["rxdb-premium"]` in a parent `package.json`,
`RXDB_PREMIUM` env, or a parent `.env`. The license lives on this machine in
`~/Projects/monorepo-v2/.env` (`RXDB_PREMIUM=...`). A **fresh monorepo worktree can't see it**
(the installer only walks parents from `node_modules/rxdb-premium`, and the worktree is under
a different path), so **copy `.env` into the worktree root** (it's gitignored). Note: `pnpm
web build` re-runs a deps check → `pnpm install`, so the `.env` must be present (copying a
built `dist` alone is wiped by the reinstall). ⚠️ rxdb's installer prints the license token in
its logs.

### A free-plugin DRAFT does NOT create a git tag; pro pulls free via `dev-main`
Corrects the 1.9.5 memory ("the draft-create step tags it; free only needs to be tagged
before pro"). A GitHub **draft** release creates no git tag until **published**. But pro
doesn't need the tag at all: pro's `composer.json` requires `wcpos/woocommerce-pos: dev-main`
(a VCS **branch**, not a tag, not WP.org), so pro only needs free's `main` HEAD to carry the
new code. Order in practice: merge free → merge pro (pro bundles free `dev-main` = 1.9.6).
Publishing free is still required to ship it to users (tag + WP.org), but is not a
prerequisite for the pro build.

### Monorepo release is created MANUALLY
No monorepo workflow creates the app release (v1.9.4 was authored by `kilbot`). Create it with
`gh release create v1.9.6 --repo wcpos/monorepo --target <FULL-sha> --title "WCPOS App v1.9.6"
--notes ... --latest`. A **short** SHA target is rejected ("Release.target_commitish is
invalid") — use the full SHA or `main`.

### Monorepo `main` is gated by a ruleset, incl. review-thread resolution
`wcpos/monorepo` uses a **ruleset** ("Protect main"), not classic branch protection, so the
branch-protection API 404s. It requires the **`✅ Merge Gate`** check (from `test.yml`,
aggregating Deploy + E2E ×6 + Lint + Unit) and **`required_review_thread_resolution: true`**
(0 approvals). An unresolved **Codex bot** review thread blocked the merge; resolve threads
(reply + GraphQL `resolveReviewThread`) before merging. The free/pro/web-bundle repos are
less strict (web-bundle unprotected; plugins gate on their own `✅ Merge Gate`).

### `bump-submodules.yml` is broken by the ruleset (submodule pins don't auto-sync)
The monorepo release PR pins `apps/electron` at the electron `main` tip *before* the electron
1.9.6 bump, expecting `bump-submodules.yml` to sync it afterwards (1.9.4 behaviour). That
**no longer works**: the bot's direct push to `main` is rejected by the `Protect main` ruleset
(`GH013`), so both the manual dispatch and the nightly cron fail. The `apps/electron` pin on
`main`/`v1.9.6` stays at `aab0ecf` (electron 1.9.5 commit). **Reference-only — does not affect
published desktop assets** (electron release reads its *own* `package.json` = 1.9.6).
**Follow-up:** add the `PROJECT_BOT` app as a ruleset bypass actor so `bump-submodules` can
push, otherwise the pin drifts every release.

### Electron release version comes from the electron repo, not the monorepo pin
The electron `Publish` workflow's platform jobs check out `wcpos/electron` and publish
`require('./package.json').version`; the `build-expo` job checks out `wcpos/monorepo@main` for
the bundle. So: bump electron's own `package.json`, and ensure monorepo `main` is at the
target version **before** dispatching (so the bundle embeds it). All platforms published
cleanly incl. Linux `.deb`/`.rpm` and Windows (the `windows-2022` pin held).

## Process-improvement suggestions

1. **Keep one version for app/electron/free/pro** — bump all four every train (even no-change
   repos) so a plugin-only patch never desyncs the lines again. (Done manually this run.)
2. **Re-enable web-bundle auto-tag** — restore `tag-and-release.yml` or add a "create release
   on push to main" step; the manual tag is an easy-to-miss silent step.
3. **CI-build the web bundle** — a workflow that builds + commits + tags the bundle (RXDB
   secret in CI) would remove the fragile local `.env`-copying flow and the token-in-logs leak.
4. **Fix `bump-submodules`** — add the bot to the `Protect main` ruleset bypass, or have the
   release flow pin `apps/electron` at the electron bump commit directly (after electron merges).
5. **A single release-orchestration script/workflow** — the train spans ~5 repos with strict
   ordering (web bundle → monorepo → electron/mobile; free → pro); a script could bump
   versions, build the bundle, open PRs, and sequence merges/releases.
6. **Free-plugin one-command publish** — free stops at a draft; a helper to curate + publish +
   verify WP.org SVN would shorten the manual tail.
