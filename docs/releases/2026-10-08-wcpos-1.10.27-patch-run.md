## Behavior changes carried into production

- **monorepo #2429 (web via bundle v1.10.37+, desktop via electron #500, native via OTA):** the targeted OPFS recovery discards a damaged row (no valid document, or foreign bytes) in `logs`, `rx-state-host_metrics_v1`, `rx-state-sync_status_v1`, `coverageRecords`, `coverageLanes`, `schedulerTaskStates`, `queryTotalRequestStates`, `queryTotalCacheEntries` during the cleanup run that found it; non-logs discards report `disposable-row-discarded` (warning level on desktop). Replicated collections and the three existence manifests keep the refusal. One-way: discarded rows are gone; every collection in the set is rebuilt locally. Validation: Sentry 2R2 should lose its `rx-state-*` / `coverageLanes` share (58 of the last 100 events before the train).
- **free #2157 (every POS order write):** an empty `tax_ids` list resolves no keys and never consults the detector; inference counts populated keys with one grouped `COUNT(DISTINCT …)` over the active order-meta table instead of hydrating 200 orders. Semantics (newest N, most-populated key per type) unchanged. Not verified on the reporting merchant's site.
- **monorepo #2440 (1.10.28 only):** a 5xx body's `data.error.message` (+ shortened `file:line`) is quoted ahead of WordPress's boilerplate on the push error, the push event and the axios lane's toast; code-carrying rows with no engine event type are titled from the error catalogue in the till's language. 4xx bodies keep their top-level message.
