## What shipped

- **Fix — store logos missing from thermal-printed receipts**
  ([electron #298](https://github.com/wcpos/electron/pull/298)): the `wcpos-image://` cache
  scheme was never registered with `supportFetchAPI`/`corsEnabled` privileges, so the renderer's
  `fetch()` failed, the `<img>` fallback tainted the raster canvas, and the logo was silently
  dropped from ESC/POS output. Fix registers merged scheme privileges (queued *after*
  electron-serve's own registration — Electron honours only the last
  `registerSchemesAsPrivileged` call) and adds CORS headers to protocol responses.
  Not verified live against a physical printer pre-release (per the PR); worth a smoke test.

## Lessons / gotchas

- **Submodule-derived worktrees are dangerous until configured**: worktrees created from
  `~/Projects/monorepo-v2/apps/electron` inherit the submodule's shared `core.worktree`
  config, which makes `git rev-parse --show-toplevel` resolve to the `.git/modules/...` dir —
  `git add <file>` then **silently stages a deletion** (happened here: the first bump commit
  deleted `package.json` and was pushed before being caught; amended + force-pushed). **Fix
  applied to the electron submodule** (from the main submodule checkout):
  `git config extensions.worktreeConfig true` +
  `git config --worktree core.worktree ../../../../apps/electron` + shared-config
  `git config --unset core.worktree`. The `apps/web` submodule still has the trap. The same
  root cause makes `~/.claude/hooks/enforce-worktree.js` falsely BLOCK edits in such worktrees.
- **Always check `git diff origin/main --stat` before pushing a bump commit** from a
  submodule worktree — the deletion was only visible there.
- Electron-only release path otherwise matches [[wcpos-release-train-mechanics]]: bump own
  package.json → cancel push runs → dispatch `platform=all` → curate draft notes → publish.
