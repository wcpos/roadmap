## What the plan got wrong

- **Deleting `next` broke a consumer nobody listed:** the docs build's registry-mirror check read `raw.githubusercontent.com/wcpos/monorepo/next/...` (docs#574). An org code search for `raw.githubusercontent.com/wcpos` found no other.
- **The "Protect next lane" rulesets have no bypass actor**, so even an admin cannot delete the branch without disabling the ruleset for the call; the monorepo also had a classic rule with deletions off.
- **Pro's push `release.yml` would publish a changed version as `--latest` even for a beta** (the publish step is unconditional); it is `disabled_manually` since August, which is the only thing standing between a beta stamp merge and a beta served by `updates.wcpos.com`.
- **demo.wcpos.com/pos still served 1.11.9** (plugin version in the page config, `@1.11` bundle, logged in as the demo user) when the post that says it runs the beta was written.
