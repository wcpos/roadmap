## The desktop number is 1.10.4, not 1.10.3

The wrapper shipped a build numbered `v1.10.3` on 2026-08-25, ahead of the app it now carries, so
the wrapper takes the **next free wrapper number** and the desktop line sits one ahead of the app
line for the rest of 1.10.x. This is the pattern from wcpos/monorepo#1590, restated in #1604.

**Consequence to remember:** `tag-and-release.yml`'s `release-notes` job mirrors the
`wcpos/monorepo` release with the **same tag**. With the lines offset it looks for monorepo
`v1.10.4`, 404s, and writes a footer reading *"Desktop build of WCPOS app 1.10.4"* — the wrong app
version. The job leaves a **non-empty** body untouched, so the fix is to write the desktop release
body by hand (this is also what was done for `v1.10.3`). Worth making the job resolve the app
version from `package.json`'s bundled app rather than from its own tag.

## Changelog gathering

Draft changelog work had been started on 2026-08-28 (free PR #1771, changelog-only). **Twenty-two
more PRs merged on the 29th**, so the draft was ~a third of the release by the time it was cut.
Lesson: a changelog PR left open across a working day is a stale draft, not a head start — treat
the entry as something to (re)generate at bump time, and diff it against
`git log <last-tag>..origin/main` before merging.

Pro had **no** changelog PR at all; `CHANGELOG.md` still topped out at 1.10.2. Pro's entry is not
optional — `manual-release.yml` extracts the release body from it (see below).

Free's entry gained two sub-headings (**Receipt printing**, **WP Admin**) because the flat list ran
to eighteen bullets. The printing cluster (#1780, #1782, #1783, #1784, #1788, #1789, #1790) is one
story for the merchants it affects and reads badly scattered through a flat list.

## Corrections to standing notes

- **Free has TWO PHP version markers, not one** — the header `* Version:` *and* the `\VERSION`
  constant in `woocommerce-pos.php` — plus `package.json` and the `readme.txt` `Stable tag`. The
  earlier note claiming "Pro has three markers; free has one" was wrong about free.
- **Pro's `manual-release.yml` is fixed.** PR #484 landed the draft-then-publish shape: it extracts
  the top `##` section of `CHANGELOG.md` into the release body, creates the release **as a draft**,
  uploads the zip, *then* flips `--draft=false --latest`. Both prior hazards are gone — the raw
  commit-message body **and** the ~2 minute window where a published release had no artifact.
  **No manual body overwrite is needed any more**; instead, Pro's `CHANGELOG.md` entry *is* the
  release body, so it must be merchant-facing prose before the dispatch.
- **The app has no `expo-updates`**, so the native iOS/Android apps do **not** take a release over
  the air. The v1.10.2 app release note "Web and mobile pick this up automatically on next load"
  was wrong about mobile.

## Web bundle: publishing the tag is the fleet rollout

`Frontend.php` defaults the bundle ref to the plugin's own `major.minor`, so a 1.10.x plugin loads
`cdn.jsdelivr.net/gh/wcpos/web-bundle@1.10/build`. jsDelivr resolves `@1.10` to the newest `1.10.x`
tag — so **tagging `v1.10.13` rolls every 1.10.x install**, not just new ones. `Publish Web Bundle`
only pushes the built bundle to a *branch* and purges the CDN; it does not tag. The tag is the
deploy.

This release also carries the stage-1 protocol gate (monorepo #1599/#1602), so the rollout starts
the convergence clock the 1.11.0 boundary fuse is timed against. Telemetry lands via free #1760's
`pos_client_signal`.

## Run order

1. Merge free (#1771) — **before** Pro's release build. Pro's `composer.json` requires
   `wcpos/woocommerce-pos: dev-main`, a floating VCS branch with no SHA pin, resolved at build time.
2. Merge Pro (#496).
3. Free: `release.yml` leaves a **draft** → publish by hand → fires `wporg-deploy.yml`.
4. Pro: `gh workflow run manual-release.yml -f releaseVersion=1.10.3` (the `Release` workflow is
   still `disabled_manually`).
5. Bundle: dispatch `Publish Web Bundle` (`monorepo_ref=main`, `bundle_branch=main`), then tag.
6. Desktop: dispatch `tag-and-release.yml -f platform=all`, then publish the Forge draft.

## Two workflow traps hit this run

**A push to electron's `main` does not publish anything.** Only `build-expo` accepts
`github.event_name == 'push'`; all four `publish-*` jobs gate *solely* on
`github.event.inputs.platform`, empty on a push. Merging the bump produced a run that built the app
and skipped every platform publish — no release, no assets, and it looks like a successful run.
Cancel it and dispatch `platform=all`.

**Electron's `release-notes` job mirrors the monorepo release with the *same tag*.** With the
desktop line at 1.10.4 and the app at 1.10.3 it looks for monorepo `v1.10.4`, 404s, and writes a
footer claiming "Desktop build of WCPOS app **1.10.4**" — wrong. It skips a **non-empty** body, so
the workaround is to write the desktop body by hand as soon as the draft appears (the first
platform publish creates it). The durable fix is to have the job read the bundled app version
instead of its own tag.

## Release notes: too long, and too much of it never shipped

Paul's verdict on the first draft: *"way, way, way too long."* The rewrite went from a paragraph per
bullet to single lines in lay language, and then through four more rounds of cuts. Everything struck
had one of four provenances — worth checking against before writing the next set:

- **A regression introduced inside the same cycle.** Toast colours on web were broken by a `sonner`
  bump that is *itself* in this delta. Never shipped, so no merchant ever saw it.
- **Invisible plumbing.** Sync-cancel log labelling, conflict field naming. "No one would have
  noticed this."
- **Native-only fixes while mobile isn't shipping.** Android screen readers, the loading spinner,
  the Android OAuth tab. There is **no `expo-updates`** in the app, so native gets nothing over the
  air — these reach nobody until a store submission.
- **Hostile-edge audit findings.** The Logs pagination collapse (Tier 2, stripped response headers)
  and the blocked `PUT`/`DELETE` 403s (Tier 4, ModSecurity CRS defaults) were both found by
  attacking dev-free, not reported by a merchant. Both were cut — including the CRS one, whose host
  config is genuinely common in the wild.

Two wording rules also came out of it: **name the subsystem** when a fix is scoped to one ("the
**cloud** print queue" — direct WiFi/USB users must not read a cloud fix as theirs), and **describe
the symptom at its widest true scope** ("card payments" became "payments", because the failure was
in the hosted pay page every gateway goes through).

Free's entry ended at 12 lines, Pro's at 13, the app's at 8.

Checks worth repeating next run:

- **Unzip the free artifact before publishing.** Header, `\VERSION`, `Stable tag` and the changelog
  heading should all agree. Also confirm the draft's `target_commitish` is the merge commit — a
  draft older than a day silently keeps its original target while its zip is rebuilt current.
- **Unzip the Pro artifact after publishing** and read `vendor/wcpos/woocommerce-pos/woocommerce-pos.php`.
  The `dev-main` dependency has no SHA pin, so this is the only proof free merged first.
- **Verify WP.org against SVN, not the API.** `plugins.svn.wordpress.org/woocommerce-pos/trunk/readme.txt`
  and `tags/<ver>/`. The API and `downloads.wordpress.org` lag by minutes to ~30 min.
- **Verify the bundle by hashing, not by assuming.** Compare the entry filename `@1.10` serves against
  what `@main` serves, and grep the served entry JS for the version string.

### The plain-text `CHANGELOG` trap (Pro only)

Codex caught this on the release PR and it was right: Pro has **two** changelog files. `CHANGELOG.md`
is what `manual-release.yml` turns into the release body; the root **`CHANGELOG`** (no extension) is
plain text, is **not** in `.distignore`, and therefore **ships inside the zip**. Every prior release
commit updates both. Updating only `.md` would have shipped a 1.10.3 artifact whose bundled changelog
newest entry read 1.10.2.

Free is **not** the same shape: it also has a `CHANGELOG.md` that ships, but no free release commit has
ever touched it (checked v1.10.0/1/2) — it is a dev-facing accumulating draft, still titled
"WCPOS 1.8.15 — Changelog Draft" with a permanent `## Unreleased` section. Free's merchant-facing
changelog is `readme.txt`. **That stale file shipping in the free zip is worth cleaning up separately.**
