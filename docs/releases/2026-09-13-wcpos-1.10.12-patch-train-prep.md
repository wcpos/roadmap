## Draft release notes — app v1.10.12

For the monorepo release body. Electron's `release-notes` job copies this onto the desktop draft, so it must be right before the electron Publish runs.

- **The till's local database no longer grows with trading volume just from searching.** The search index wrote a history entry for every batch it processed, whether or not any searchable text had actually changed, so the stored history tracked how much you sold rather than how large your catalogue is. It is compacted only by the clean-up step, and on installs where clean-up was failing it was never compacted at all — so every start-up loaded and replayed the whole history. One store was losing its POS tab to an out-of-memory crash during trading hours.
- **Star printers: centred headings print centred, and the time prints correctly.** Centring padding was emitted as literal spaces inside a magnified run, so each pad space was as wide as each glyph and a centred double-width heading was pushed right and wrapped — one merchant's `Evans Hobby and Tech` printed as `Evans Hobb` / `y and Tech`. Magnification is also capped at the 6× the Star command can actually express, and the narrow space ICU puts into short times no longer prints as `2:05?pm`.
- **Switching stores no longer tells the cashier to sign in again for the store they just opened.** A sign-in retry still in flight from the previous store could raise the message against the new one.
- **A store whose session has expired no longer files an error report every minute.** The change-signal lane reported its tick failures under a name the de-duplication never matched, so the same failure was recorded on every tick, unbroken — 12,859 reports across 292 installs on every release from 1.10.5 onward.
- **Start-up repair of a damaged local database matches each pending change to the row it belongs to**, rather than to that row's position, and refuses a stale change for a row an index already holds under a newer entry. These fixes reached only the `@next` lane in 1.10.11, so no production install was running them.
- **Creating a virtual printer no longer fails intermittently with a certificate error.** Roughly one attempt in five hundred generated a serial number the certificate encoder rejected.

Internal, deliberately left out: the two CI-plan fixes, Sentry source-map upload on bundle publish, `docs(context)`.

## Draft plugin notes — free + Pro 1.10.12

Free's `readme.txt` changelog and Pro's `CHANGELOG.md` top section (which **is** Pro's merchant-facing release body). Both carry the app notes above, plus these plugin-only lines:

- **Cloud print and template reprints: a heading asked to be double-wide printed double-high.** The `GS !` command carries width in the high bits and height in the low bits; the emitter built it the other way round. Square sizes are bit-symmetric and 2×2 is what nearly every template uses, which is why it went unseen — and why the one test pinning the byte asserted the single value that cannot tell the two conventions apart.
- **Cloud print: centred headings are padded in printed columns, not characters** — the server-rendered twin of the Star centring fault above.
- **A product or order carrying an enormous meta value no longer takes down the request.** One store was losing about 22 requests an hour — roughly 1,150 fatal errors since 7 September — to a single record whose one meta value serialised to about 1.25 GB of JSON. The value is now withheld rather than re-encoded, so the record loads instead of the client retrying it all day.

### Two corrections I got wrong in-flight, recorded so they are not repeated

1. **`wporg-deploy.yml` builds from the tag, it does not use the release asset.** When free 1.10.13's zip upload failed I warned that publishing the asset-less draft would deploy "with no artifact behind it". Wrong: the workflow checks out `v<version>` and runs the full build itself. Paul published, and WP.org got a correct 1.10.13. **Read the workflow before characterising the risk** — I had the file open and drew the opposite conclusion from it.
2. **A missing release asset is not recoverable by re-triggering once the tag exists.** `release.yml`'s version check compares against `git describe --tags`, so after publishing, a new push sees `v$VERSION == $LAST_TAG` and skips the build. The empty-commit re-trigger PR (#1978) became a no-op and was closed. **Gap worth fixing: `release.yml` has no `workflow_dispatch`**, so a transient upload failure cannot be recovered without a version bump.

### Verification notes worth keeping

**A changed sha is not proof the fix is in the worker.** Re-vendoring `opfs.worker.js` from v1.10.22 changed its sha256 (`53f12342…` → `899a6bdf…`), but grepping for the `postinstall` patch markers (`__wcposApplyChangelogOperation`, `__wcposLinkIndexStates`) found them in **neither** the old nor the new worker. That reads like the re-vendor being pointless, and it is not: `apps/main/public/opfs.worker.js` is a checked-in pre-built artifact, rebuilt separately from the rxdb-premium `postinstall` patches, so it never carries those marker names. The real proof is **`__wcposIndexStates`** — the sibling index-state linking from the identity fix set — present in the v1.10.22 worker, absent in v1.10.21's, plus the vendored copy being byte-identical to the monorepo source at the release SHA. Free's own drift check (sha256 against the highest `v1.10.x` bundle tag) then agrees.

**Electron's `release-notes` job is genuinely fixed.** With desktop 1.10.15 and app 1.10.12 diverged — the exact case that used to 404 and footer the wrong app version — it read the app release via `.monorepo-ref` and footered "Desktop build of WCPOS app **1.10.12**" correctly. No hand-written body was needed. First train to exercise that since the standalone migration.

**macOS x64 DMG flaked once** on `hdiutil detach /Volumes/WCPOS` → "No such file or directory", while arm64/Windows/Linux all succeeded. Not the `onlyBuiltDependencies`/`macos-alias` class (that breaks every DMG). `gh run rerun --failed` cleared it and Forge appended to the existing draft rather than splitting it.
