## Structural blockers hit (and durable fixes)

A promotion PR is a shape the per-PR gates had never seen; three policy checks misfired:

1. **Merge Gate fix-bot discipline re-litigates all promoted history** — `wcpos-agents[bot]`
   commits that landed on `next` before/under different rules fail the `Tested:`-trailer check,
   and trailers can't be added to published history. **Fix (durable):** `is_lane_promotion_pr()`
   in `.github/scripts/merge-gate.sh` — same-repo head `next`/`promote/*` → base `main` skips
   only the per-commit discipline; content checks still gate. Forks/non-main bases fail closed.
   Landed on main via free #1604, pro #440, monorepo #1236 (with harness cases).
2. **Monorepo `main` had no `merge-gate.yml`** — the gate moved from `test.yml` (main) to a
   `pull_request_target` workflow (next), but `pull_request_target` loads from the PR **base**
   branch, so the promotion PR could never report the required "✅ Merge Gate". Fix: land
   next's `merge-gate.yml` on main first (part of #1236). Promotion gate then triggered by
   close/reopen of #1235 (no synthetic push needed).
3. **Pro's lane-aware composer constraint** (correctly) demands `dev-main` on PRs targeting
   main, but `next` carries `dev-next` and must keep it. **Promotion shape for pro:** a
   `promote/1.10` cut of `next` + one commit flipping the pin. PR #439 (head `next`) closed,
   replaced by #441 (head `promote/1.10`). This is the permanent pattern for pro promotions.

Non-blocking failures (expected, ignorable on promotion PRs):
- **REST lane coverage ratchet** red X: diffs v1-only test cases against the main merge-base,
  so the whole cycle's tests read as "new". Not a required check; self-heals post-promotion
  (future merge-bases include the cases).
- **monorepo dependency-review** red X on the giant lockfile diff: not part of Merge Gate.
- **Pro PHPStan/Smoke before free merges**: pro 1.10 + free `dev-main`(=1.9.17) mismatch;
  reruns green after the free promotion lands.

## Incidents during the run

- **"Automatically delete head branches" DELETED `next` in free and electron** when the
  promotion PRs (head `next`) merged. Recreated `next` at the main tip (correct
  post-promotion state) and added a "Protect next lane" ruleset (deletion rule) in all
  four repos. **Future promotions should use `promote/X.Y` cuts in every repo** (the gate
  already allows `promote/*`) — then auto-delete only eats the disposable cut.
- **The pro `main`→`next` back-sync silently carried `dev-main` onto next** (predicted:
  next hadn't touched composer.json after the promote-cut ancestor). Fixed the pin back to
  `dev-next` inside the merge commit before pushing. Pro's lane check on next-push CI
  verifies it.
- **Monorepo back-sync**: API merge main→next (bcd502c6). Free/electron converged via the
  branch recreation.
- The push-to-main monorepo Deploy failed pre-promotion (old June-era deps vs current
  runners: secp256k1 gyp). Expected to self-heal now main has 1.10 deps — verify on the
  next main push.
