Waiting buys no evidence on it.

## Risk read (per item, verified against the diffs, not the PR claims)

- **The Logs batch (#2663, #2669, #2670, #2671, #2673, #2676, #2678, #2681) — the one to watch.** ~9,000 lines added, mostly tests and copy, but it rewires severities in the sync observer, the HTTP transport row, every money-path toast and the checkout gateway-load retry (bounded retries after a cancelled sign-in; Process Refund held while gateways load). Each PR has real-RxDB or jsdom tests with mutation checks; none was run on a device or live store ("Not verified live; needs a release to reach demo" on #2663). The behaviour that matters to a cashier is unchanged where it counts: the server stays authoritative, pushes still retry, dead letters still park. What changes is what the screen says. Medium by surface, low by evidence.
- **#2670 D1 fix.** A fresh Bottleneck queue is created before the stale one is stopped; the wake test fails with the old order. Low. **D3**: conflicts are now recognised by RxDB's real status / the worker's `code` field instead of a substring; lookalikes rethrow as SYNC999. A storage error that *was* a real 409 but arrives without the code field would now surface as SYNC999 instead of a quiet conflict — louder, not lost. Low.
- **#2780 / #2781 web bundle.** Charts were already lazy; the validator is dev-only; Sentry loads after consent (captures before init are held and drained; a failed load is caught); each non-English date-fns locale is one ~3 KB chunk with English until it lands. A merchant offline on a cold cache in a non-English language sees English date formats until the chunk loads. Measured on the release-shaped export; the train should re-run `scripts/web-bundle-composition.mjs` on the published export and record both totals. Low.
- **free #2335.** One new transient per text domain and locale; stale file on disk still loads during the back-off; PHPUnit ran in CI only (local wp-env ports were held). Low.
- **Translations 2026.10.7.** Pinned on every main for a day; the bundle picks it up at build. Low.

## B1 — app notes (app 1.11.3, GitHub release body and electron footer source)

- **Checkout and refunds no longer stop working after the browser tab or desktop window wakes with sync requests still in flight.** Every later request to the store failed until the page was reloaded. Web and desktop only.
- **A completed order no longer logs "a change on this device clashed with an edit in your store".** The first retry of a save was reported as a conflict even though the order had saved.
- **Logs and toasts alarm only when there is something for you to do.** A retry the app handles itself is now an information row; a warning names the record, says what happened and links to where it is fixed, and never tells you to clear the device's data.
- **A sale that times out while sending is reported as "still on its way", not as failed, so it is not entered twice.** The same applies to a new customer that has not reached the store yet.
- **A refund whose result could not be confirmed says so and tells you to check the order before trying again.**
- **A storage error whose text happened to contain "409" or "CONFLICT" is no longer reported as a clash with your store.** The real error is shown instead.
- **Web: the first download is a fifth smaller.** Error reporting and date-format languages load only when they are needed.
- Developers: translations updated to 2026.10.7.
