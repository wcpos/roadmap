# 2026-11-06 — WCPOS 2.0.0 GA: run plan

**Status: plan, not a run record.** Written 2026-11-06 from the live state of every repo, the promotion plan (`2026-11-01-wcpos-2.0-promotion-and-beta-plan.md`, Phase 6), the two beta run records and `RELEASE-CHECKLIST.md`. Nothing in it has been executed. The run record goes in a separate file when it runs. Ticket: roadmap#549, under the 2.0 GA epic roadmap#543.

Paul's rule for this work: prepare to the brink and stop. Every leg below that publishes or moves a production switch runs on Paul's go.

## The shape in one paragraph

Stamp `2.0.0` on `main` in free, Pro, electron and the app, from the notes in #496. Run the train with every production switch on: app tag, web bundle on the `@2.0` lane, free to WP.org, Pro, desktop, mobile to store review. Promote the seven extensions and merge the catalog PR last among the releases. Then re-cut `next` in free, Pro, monorepo and electron, in that dependency order, and walk the consumer list. Then retire the beta surfaces and flip the docs. 1.11 stays alive on `1.11.x`, and from the moment v2.0.0 is `latest` its releases must publish non-latest (#544).

## Traps

**Carried from the promotions**

- `promote/X.Y` heads, never `next` itself: auto-delete ate `next` twice.
- A promote PR merges with a merge commit, never a squash, so `main` stays a superset of `next`.
- A promotion PR re-litigates a cycle of bot reviews. Triage to issues and resolve the threads with links; do not fix cycle-old code in the promotion diff.
- The bundle gate wants the push Deploy run for the exact sha. Pass the sha, never `main`.
- A reused draft keeps the first push's target. Delete it, never retarget.
- Free's zip is flat.
- Pro's composer pin: `dev-main` on `main`, `dev-next` on `next`, `1.11.x-dev` on `1.11.x`. The lane check catches a wrong pin only on the next push.
- WP.org propagation lags. Do not re-run a deploy because the page has not moved.
- Electron: dispatch with the tag as explicit ref, and cancel the push run.
- `demo.wcpos.com` is the surface that gets forgotten: beta 1 and 2 left it on 1.11.9.

**New for GA**

- **Monorepo's `next` ruleset refuses creation.** "Protect next lane" 20878656 has `do_not_enforce_on_create=false` and a required check.
- **#2560.** No manual 1.x WP.org deploy from `main`. The dispatch on `main` writes trunk.
- **1.11 translations pin.** A hand bump on `1.11.x` to a main tag loses 81 keys. Dispatching `push-js-strings.yml` from `1.11.x` overwrites 2.0's source strings. New 1.11 strings go on the translations `1.11.x` lane under a side tag.
- **`latest=true` flips at GA.** Before GA a 1.11 dispatch needs `latest=true`; after GA the default is false and `true` is refused. The lanes derive which side they are on from the repo and fail closed.
- **`SHIPPED_LINE`.** The wiki bump fails every page still marked `["1.11"]`, by design. Do not bump it in a hurry on GA day.
- **Extension zips.** Mollie and sumup ship their tests directories.
- **`next`-lane electron prereleases** may feed the account Beta card if it stays. Remove the card first (7.3).
- **Order of the catalog.** It goes last among the releases, or a 1.11 till is told to want a version that does not exist yet.
