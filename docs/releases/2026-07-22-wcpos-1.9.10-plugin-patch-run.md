# WCPOS Release Run Reference — 2026-07-22 (1.9.10 plugin-only patch)

A **plugin-only patch** release of the free and Pro PHP plugins (no monorepo / web-bundle /
electron / mobile this cycle). Five free-plugin fixes, no Pro-only changes. The notable event of
this run was a **release-workflow pin that would have shipped Pro 1.9.10 with free 1.9.9 code** —
caught by bot review on the Pro PR and fixed before merge.

## Why plugin-only

Surveyed all five repos before scoping the release:

- **Monorepo (`main`)** — 13 commits since `v1.9.7`, all non-user-facing: two translation-version
  chores, an axios `1.17.0 → 1.18.0` bump, and an E2E test-plan doc regeneration. Nothing to ship.
- **Web bundle** — already at `v1.9.10` (built 2026-07-15 during the 1.9.7 train), zero commits
  since. A rebuild would have delivered only the translation-version bump.
- **Electron** — at `v1.9.9` (published 2026-07-18; **that release has no run doc** — the
  2026-07-18 doc covers 1.9.8 only). Since then: a translation chore and
  [electron #302](https://github.com/wcpos/electron/pull/302), the main-process Web Serial / WebHID
  scanner device selection. **Its renderer counterpart —
  [monorepo #748](https://github.com/wcpos/monorepo/pull/748) — is on `next`, not `main`.**
  Electron's `tag-and-release.yml` checks out `wcpos/monorepo` with no ref (→ default branch
  `main`), so a desktop patch today would ship device-select handlers and preload channels with no
  caller. Should be inert, but the feature would not reach users; deliberately skipped.
- **All the 1.10 work** — camera barcode scanning, scanner transports, scan sounds, FlexSearch
  mid-word product search — is on monorepo `next` (**211 commits ahead**). Not patch material.

## What shipped

All five are free-plugin changes; Pro carries them via the Composer bundle.

- **Stale variable parent prices** ([free #1271](https://github.com/wcpos/woocommerce-pos/pull/1271)):
  a simple product converted to variable kept its pre-conversion price in `/wcpos/v1/products`.
  The top-level `price` now reflects the minimum current visible variation;
  `regular_price`/`sale_price` stay blank so independent variation minima can't fake a sale.
- **Fatal error in translated receipt previews** ([free #1274](https://github.com/wcpos/woocommerce-pos/pull/1274)):
  the Czech translation of `Summer Sale (%s%%)` is `Letní akce (%s %)`; passing that to `sprintf()`
  parsed the literal `%` as a second directive → `ArgumentCountError` before the receipt editor
  could load. Fixed by substituting `%s` directly and normalising `%%` without routing
  translator-controlled percent signs through `sprintf()`.
- **Cloud printer polling** ([free #1279](https://github.com/wcpos/woocommerce-pos/pull/1279)):
  generated Star CloudPRNT / Epson SDP poll URLs were missing the `wcpos=1` marker that registers
  the REST routes, so copied URLs 404'd. Also accepts Star's documented `2xx` completion family
  (eg: `211 Paper Low`) as success, and adds rate-limited, token-free diagnostic logging.
- **Missing POS favicon** ([free #1281](https://github.com/wcpos/woocommerce-pos/pull/1281)):
  stale icon URLs returned 404; now points at shipped `assets/img` icons with a regression test
  asserting every referenced plugin asset exists.
- **Refresh button on the Extensions screen** ([free #1283](https://github.com/wcpos/woocommerce-pos/pull/1283)):
  optional `force` arg on `GET wcpos/v1/extensions` clears the 1-hour catalog transient, mirroring
  core's `?force-check=1`.

Plus `.pot` refreshes and translation version `2026.7.2` in both plugins.

## ⚠️ The Composer pin — near-miss

**The Pro release workflows pin free to an exact commit, not floating `dev-main`.** Both
`.github/workflows/release.yml:72` and `manual-release.yml:48` run:

```
composer require "wcpos/woocommerce-pos:dev-main#<SHA>" --no-update
composer install --no-dev
```

`composer.json` says `"wcpos/woocommerce-pos": "dev-main"`, which is what earlier run docs and
notes described — but the **workflow pin overrides it**. At the start of this run the pin was
`aab41055`, free's `chore: release 1.9.9` commit: **36 commits behind `main`**. Merging the Pro
bump as-is would have published a Pro 1.9.10 artifact labelled 1.9.10 while bundling free 1.9.9 —
none of the five fixes above, silently.

Caught by **Greptile and Codex review threads on [pro #376](https://github.com/wcpos/woocommerce-pos-pro/pull/376)**
(both P1, independently). Verified locally (`git merge-base --is-ancestor`), then repointed both
workflows to `367cf158` (free's 1.9.10 merge commit) in commit `beb14f4` before merging.

**This is a manual step every plugin release** and it fails silently — the build succeeds, tests
pass, and the artifact is simply stale. Verify the pin against free `main` on every Pro release.

**Follow-up worth doing:** the pin defeats the floating `dev-main` constraint that
`composer.json` already expresses. Either drop it (let `dev-main` float) or derive it in-workflow
from free's `main` tip, so it can't silently rot.

   [pro v1.9.10](https://github.com/wcpos/woocommerce-pos-pro/releases/tag/v1.9.10). Its
   auto-generated body was raw dependabot noise, so it was **overwritten with curated

   `includes/API/Extensions.php`, favicon links in `templates/pos.php`, `wcpos=1` marker in
   `includes/Template_Router.php` + `includes/wcpos-functions.php`).
