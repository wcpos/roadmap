## Follow-up automation shipped this run

**Electron release notes are now auto-filled** (electron PR #296, merged): a
`release-notes` job in `tag-and-release.yml` runs after the platform publish jobs and
copies the body of the **wcpos/monorepo release with the same tag** onto the desktop
release, appending the standard desktop footer. Footer-only fallback happens only on a
clean 404 (other API errors fail the job); a non-empty body is never overwritten (with a
just-before-write re-check), so hand-curated notes and re-runs of failed platform jobs
are safe. The draft-publish decision itself stays manual. Reminder: pushes to electron
`main` trigger a `Publish` run (Linux publishes on push) — keep cancelling the redundant
run after non-release merges.

## New lessons

### `pnpm web build` resets the `apps/web` submodule branch (detached HEAD trap)
The build's deps check re-runs `git submodule update`, which **detaches `apps/web` back to
the pinned commit** — a branch created in the submodule before the build gets left behind,
and a commit made after the build lands on a detached HEAD. Symptom: `gh pr create` says
"No commits between main and <branch>" even though the push "succeeded" (it pushed the
stale branch ref). Fix: after building, `git checkout -B <branch> <commit>` in the
submodule, rebase onto `origin/main`, force-push. Or: create the branch only *after* the
build completes.

### pnpm-lock churn from initializing `apps/electron` in the worktree
Initializing the electron submodule in a fresh worktree makes pnpm add its importer to
`pnpm-lock.yaml` (~6k lines). Restore the lockfile before committing the release bump.
