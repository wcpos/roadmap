## Notes worth keeping

- **A plugin-only patch train is about 18 minutes wall-clock** from the fix landing to Pro live: #2371 merged 17:48:50, free cut 17:50, free merged 17:54, draft verified and handed over 17:58, Paul published 17:59:58, WP.org deployed 18:02, Pro merged 18:04, Pro live 18:07 UTC. The free cut can open ready (not draft) on a plugin-only train, since nothing upstream gates it and readying a draft only re-triggers Codex.
- **`--admin` is still needed on the free and Pro bump merges.** The 1.11.4 record said "`--admin` adds nothing" once `review-gate` is green; wrong. The "Required checks (auto-merge)" ruleset waits on the PHP matrix and a plain `gh pr merge --merge` is refused ("the base branch policy prohibits the merge"); `--admin` bypasses that ruleset (admin role is its bypass actor) and the gate's requirement is met by the green status. Sequence: Codex pass on the head → gate re-run → `review-gate` success → `--admin`.
- **Sync-conflict resolution: "take main's side" is not always right.** In a conflict hunk where next deleted code that main left alone (next's redundant-test sweep), main's side of the hunk silently restores it. Check `git log <base>..<next> -- <file>` for deliberate next-side deletions in the hunk before choosing a side; the fresh-Opus review caught it this time.
- **Codex can misread a merge commit's parents on a sync whose net diff is one file.** It claimed `89402668` had a single parent; the API showed two. Answer with `git/commits/<sha>` parents and `compare/<main>...<head>` behind_by 0, resolve, re-run the gate.
- Pro's `manual-release.yml` was dispatched 5 min after the free publish and Pro was live 7 min after it; the by-tag asset count was 1 straight away (no stale-cache shape this train).
