# The gallery: route contract, baseline home, captures

_Decided 2026-09-18 by Paul in the grilling for [Decide the gallery](https://github.com/wcpos/roadmap/issues/352), part of the [UI overhaul for 1.11.0 map](https://github.com/wcpos/roadmap/issues/282). The minimal route is item 1a of [the landing order](2026-09-18-landing-order.md); this page is what `/to-spec` writes it from. Inputs: [the scale and density page](2026-09-18-scale-and-density.md) (six cells, not a rebuild of the tree), [the platform-split page](2026-09-18-platform-split.md) (two cells per idiom key), [the feedback-states page](2026-09-18-feedback-states.md) (a cell per applicable state), the [token block research](https://github.com/wcpos/monorepo/blob/research/token-block-on-uniwind/.claude/research/2026-09-18-token-block-on-uniwind.md) (nothing in the stack reports an uncompiled construct; the gallery is the only instrument)._

## In one paragraph

The gallery is a route inside `apps/main`, mounted only in a gallery build, shot by its own Playwright project as a job in the Test workflow, because PRs to `next` skip the E2E suite (ruling 2026-09-03). One page per component; scale step, pointer floor, feedback state and idiom key are cells in one tree; the theme is a page-level query. Baselines are Linux-only element PNGs committed in the monorepo beside the shoot, written by CI, zero pixels of difference allowed. Screen captures are PR artifacts embedded in the PR comment and swept on close, never committed.

## 1. Where it lives and where it is shot

| | Decision | Why |
|---|---|---|
| Home | A route in `apps/main`, `/gallery/<component>`, mounted only when the build carries the gallery flag | The cells render through the real pipeline: the same `expo export`, the same `global.css`, the same root `ScopedVariables`. A separate Vite app would shoot something other than what ships, which is the failure the gallery exists to catch. Merchants never see the route. |
| Shoot | A dedicated Playwright project in `apps/main`, separate from the E2E projects | The E2E suite needs a store; the gallery needs a static build and no network. |
| CI | A job in the Test workflow (runs on every PR to `next` and `main`), on PRs touching `packages/components`, `packages/core/src/screens`, `apps/main/global.css` or the gallery; one web build with the flag, served statically | The Deploy workflow's E2E job is skipped on PRs to `next`, so a gate there would never fire on the lane the program lands in. |

Rejected: a separate `apps/gallery` (second bundler, second Uniwind wiring); the route shipped unlinked in the production bundle (a dev surface for every merchant).

## 2. The route contract

- **One page per component.** `/gallery/<component>` renders a grid of every cell the component declares.
- **Cells are declared beside the component**, in a `gallery.tsx` next to its `index.tsx`, so a PR that adds a state or a split adds its cell in the same diff. A component with no `gallery.tsx` has no cells, and the definition of done (landing order, DoD C) fails it.
- **Scale and floor are per cell.** Each cell wraps its story in its own `ScopedVariables` for the step (Compact, Regular, Spacious) and the pointer floor (coarse, fine): six cells, one tree.
- **States and idiom keys are rows** of cells: one row per applicable feedback state, two rows per idiom-split key (fine/coarse or phone/wide).
- **Theme is a page-level query**, `?theme=light|dark`, because dark mode is a Uniwind colour-scheme variant, app-wide, not a variable a cell can scope. The shoot loads each page twice.
- **Single-cell zoom**: `?cell=<id>` renders one cell alone at full size for a human to inspect.
- **The shoot takes element screenshots**, one PNG per cell per theme, never a page screenshot.
- A component that reads the pointer through a media query instead of the floor variable will not respond per cell. That is a finding against the component, not the gallery.

## 3. Baselines

| | Decision |
|---|---|
| Home | In the monorepo, Playwright's own convention: `<spec>-snapshots/<cell>-<theme>-linux.png` beside the shoot |
| Who writes them | CI only. Baselines are never generated on a Mac. A PR that intends a visual change gets new baselines by a label or dispatch that runs the shoot in update mode and commits the PNGs to the PR branch, so old and new sit in the PR diff. |
| Tolerance | **Zero pixels of difference.** Playwright's per-pixel colour threshold stays at its default 0.2 to absorb anti-aliasing; animations disabled; caret hidden. A cell that will not settle to zero is fixed in the cell, never by raising the tolerance (the standing rule: fix the instrument, never the multiplier). |
| Reviewer | The PR's reviewer under the standing merge authority, with the Playwright diff report as the job's artifact. Paul reviews baselines live only where the landing order already has him live: the pilot, the register switch, the token pass. |

Size: about a thousand cells at two themes, around 20 MB for the first set; each tier restyle and the token pass rewrite their cells, so the program adds on the order of 100 to 200 MB of history. Rejected: a sibling repo (moves the growth, splits the review from the code that caused it, needs a token and a clone); Git LFS (bandwidth on every checkout, a bill within the program).

## 4. Screen captures (DoD G)

PR artifacts only. The twelve captures per screen state (tablet and phone, light and dark, three steps) are attached as a workflow artifact and embedded in the PR comment as a grid through the per-PR screenshot release the E2E job already uses, swept on close by the existing nightly job. Never committed: they are review material, and the record of what shipped is dev-next plus the committed gallery cells. Screen-level diffs are not attempted; the 24 composed pieces have their own cells, which is the instrument for composed regressions.

## 5. What `/to-spec` writes from this

The minimal route (landing order 1a): the flag, the route file, `gallery.tsx` for `input`, `button`, `select`, `combobox`, `text` and `icon`, the Playwright project and its config, the Test job with its path filter and update mode, and the first baseline set for those six. Every later component PR adds its `gallery.tsx` and its baselines.

## Glossary

- **Cell** — one rendering of one component at one step, one floor, one state and one idiom key; the unit of the baseline.
- **Story** — the code in `gallery.tsx` that renders a component in one state for the gallery.
- **Gallery build** — an `expo export` with the gallery flag, the only build that mounts the route.
- **Baseline** — the committed PNG a cell is diffed against; Linux, written by CI.
- **Capture** — a full-screen PNG of a switched screen for human review; a PR artifact, never a baseline.
