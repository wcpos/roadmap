## 2. POS order-authorisation gate
- `AjaxHandler::authorized_order(array $request)` resolves `order_id` via `wc_get_order(absint(...))`. `OrderAccess::can_mutate_order($order,$request): bool` accepts **manage_woocommerce OR matching nonempty order_key OR valid payment_request_token**. A nonce alone does not grant order access. `includes/AjaxHandler.php:421-441`, `includes/OrderAccess.php:20-33`
- For logged-in users or `manage_woocommerce`, nonce action `sqtwc_payment` is required **unless** a valid order key or payment token is present. Anonymous requests still need the order key/token. `includes/AjaxHandler.php:427-438`, `includes/AjaxHandler.php:575-576`
- `PaymentRequestToken::create(int $order_id,int $expires): string` returns `base64(JSON({order_id,expires})).hex-HMAC-SHA256(payload,wp_salt('auth'))`; `verify()` uses `hash_equals`, order-ID equality and `expires >= time()`. No token storage or fixed TTL is declared. `includes/PaymentRequestToken.php:20-61`
- Supplied payment markup emits `data-order-key`; it does not mint a payment token. JS additionally supports a caller-supplied `data-payment-token`, sent as `payment_request_token`. `includes/Gateway.php:867-885`, `assets/js/payment.js:802-808`
- All four checkout AJAX handlers invoke this gate: create, status, cancel, detach. Internal `cancel_terminal_checkout_for_order()` assumes prior authorization. `includes/AjaxHandler.php:54-67`, `includes/AjaxHandler.php:188-195`, `includes/AjaxHandler.php:236-261`, `includes/AjaxHandler.php:320-327`
- Not covered by that gate: webhook uses Square signature verification; admin AJAX uses capability plus `sqtwc_admin` nonce; OAuth uses capability plus action-specific nonce/state; Square POS-app callback requires JSON state `{o:order_id,k:order_key}` and matching key, then provider verification. `includes/WebhookHandler.php:119-128`, `includes/Plugin.php:648-657`, `includes/Plugin.php:310-315`, `includes/Services/SquareOAuth.php:215-228`, `includes/PosCallbackHandler.php:60-73`
- POS request detection: **ABSENT** as a distinct authorization context. Rendering resolves query var `order-pay`, then `$GLOBALS['wp']->query_vars['order-pay']`; asset loading recognizes checkout/pay-page or filter `sqtwc_enqueue_payment_assets`. No POS-specific request header is added. `includes/Gateway.php:194-208`, `includes/Gateway.php:693-705`, `assets/js/payment.js:761-808`

## 4. Payment lifecycle on the server
- **Entry:** `Gateway::process_payment(order_id)` returns failure plus WC error notice for missing order; paid order → return URL; unpaid order → authenticated order-pay URL. It does not create a Square checkout. `includes/Gateway.php:653-672`
- **Start:** `AjaxHandler::create_terminal_checkout_for_order(order,device_id)` rejects paid orders, previously recorded partial funds/payment IDs, and active checkout IDs. New attempt uses separate attempt/idempotency UUIDs; retry of a checkoutless attempt reuses its original device and exact saved request. `includes/AjaxHandler.php:77-120`
- Saved request `_sqtwc_attempt_request` shape: `{amount:int,currency,device_id,reference_id:"woocommerce_order_<id>",idempotency_key,deadline_duration:"PT5M",note,skip_receipt_screen:bool,collect_signature:bool}`; amount comes from the server order; note is store/order number, capped at 500 characters. `includes/AjaxHandler.php:108-119`, `includes/AjaxHandler.php:561-569`
- `OrderMeta::start_attempt()` saves before calling Square: `_sqtwc_current_attempt_id` UUID, `_sqtwc_checkout_idempotency_key` UUID, request array, `_sqtwc_checkout_id=''`, `_sqtwc_checkout_status='PENDING'`, `_sqtwc_checkout_updated_at=''`, `_sqtwc_device_id` string, `_sqtwc_attempt_started` epoch, `_sqtwc_square_checked_at=0`; indexes the order. `includes/Services/OrderMeta.php:44-55`
- Create makes at most two adapter calls for retriable failures. Exhausted retriable/indeterminate responses preserve the attempt; definitive failures close it, except `IDEMPOTENCY_KEY_REUSED`. Successful create stores checkout ID/status/optional updated-at and an info log. `includes/AjaxHandler.php:122-163`
- **Poll:** paid-order fast path returns `COMPLETED`/receipt URL. Final cached states or absent checkout IDs avoid fetching; otherwise `_sqtwc_square_checked_at` throttles provider reads to five seconds unless `force=1`. Fetch timestamp is persisted before `get_checkout()` and `CheckoutReconciler::reconcile()`. `includes/AjaxHandler.php:196-225`, `includes/AjaxHandler.php:373-378`
- **Reconcile:** `CheckoutReconciler::reconcile(checkout array,order,SDK options=[]): array` accepts current or explicitly abandoned checkout IDs with matching order reference, rejects older `updated_at`, and recognizes `PENDING/IN_PROGRESS/CANCEL_REQUESTED/CANCELED/COMPLETED`. State cache uses `_sqtwc_checkout_status` and `_sqtwc_checkout_updated_at`. `includes/Services/CheckoutReconciler.php:42-105`, `includes/Services/CheckoutReconciler.php:344-361`
- Completion fetches each Payment; accepts `COMPLETED` or `APPROVED` with card status `CAPTURED`, validates numeric total/order currency and tip currency. `CANCELED` + `TIMED_OUT` with captured payment IDs is reconciled as completion. `includes/Services/CheckoutReconciler.php:67-82`, `includes/Services/CheckoutReconciler.php:310-335`
- `_sqtwc_payment_ids` stores deduplicated string IDs; `_sqtwc_collected_amount` and `_sqtwc_tip_amount` store cumulative minor-unit integers. Tip is at least total overage. Undercollection adds a note and moves order to `on-hold`; sufficient collection calls `payment_complete(first new/existing payment ID)` after closing the attempt. `includes/Services/CheckoutReconciler.php:131-156`, `includes/Services/CheckoutReconciler.php:199-253`
- Additional payment on an already-paid order records `_sqtwc_duplicate_payment_ids` string array, an alert note and error log, preserving the original payment record. `includes/Services/CheckoutReconciler.php:158-196`
- **Cancel:** matching checkout/device required; fetch-and-reconcile before cancel, skip cancellation when already final, send provider cancel, fetch-and-reconcile again. Inconclusive cancellation does not clear the attempt. Final cancellation adds reason note/log and closes the attempt; it does not set WC order status `cancelled`. `includes/AjaxHandler.php:274-311`, `includes/Services/CheckoutReconciler.php:271-298`
- **Detach:** archives known checkout ID in `_sqtwc_abandoned_checkout_ids` string array, closes attempt as `abandoned`, clears cached status/time and returns `IDLE`; it makes no Square cancellation request. Checkoutless attempts can be detached using matching device ID. `includes/AjaxHandler.php:320-360`
- `OrderMeta::close_current_attempt()` appends `_sqtwc_attempt_history[] = {attempt_id,checkout_id,status,device_id,started,ended[,cancel_reason]}`; clears active identity fields, deletes request snapshot and resets checked-at. History is not capped here. Pending abandoned IDs retain reconciliation indexing. `includes/Services/OrderMeta.php:65-107`
- **Lock:** `OrderLock::{acquire,release,with_lock}` is reentrant per instance. Primary MySQL advisory name `sqtwc_order_<order_id>_<blog_id>`, five-second wait; fallback non-autoload option `sqtwc_lock_<order_id>="ownerToken|epoch"`, takeover after 300 seconds, owner-checked release. AJAX reloads orders after acquisition. `includes/Services/OrderLock.php:32-77`, `includes/Services/OrderLock.php:83-155`, `includes/Services/OrderLock.php:163-191`, `includes/AjaxHandler.php:388-400`
- **Webhook:** same lock/reconciler; `_sqtwc_processed_event_ids` retains newest 50 IDs. Duplicate event returns 200; reconciliation exceptions restore prior IDs and return 500. `includes/WebhookHandler.php:169-231`, `includes/Services/OrderMeta.php:140-144`
- **Cleanup:** `PaymentSweeper` cron hook `sqtwc_sweep_payments`, schedule `sqtwc_ten_minutes` every 600 seconds; deactivation unschedules it. Queue uses non-autoload options `sqtwc_reconcile_<order_id>` containing oldest indexing epoch. Each sweep selects oldest 25, fetches active checkouts older than 600 seconds and all abandoned IDs, reconciles and removes finalized work. `includes/Services/PaymentSweeper.php:17-20`, `includes/Services/PaymentSweeper.php:50-103`, `includes/Services/PaymentSweeper.php:162-168`, `includes/Services/PaymentSweeper.php:208-253`, `includes/Services/OrderMeta.php:113-131`
- Legacy queue seeding uses an uncapped `wc_get_orders(meta_query...)` once, marked by option `sqtwc_reconcile_seeded`. No sweeper expiry of checkoutless attempts: selection requires checkout ID; remaining attempt ID keeps the queue entry. `includes/Services/PaymentSweeper.php:108-154`, `includes/Services/PaymentSweeper.php:216-250`
- External status transitions to `processing/completed/cancelled/failed` trigger `Plugin::cancel_open_attempt_on_order_status_change()` for known active checkout/device; SDK options `timeout=8.0,maxRetries=0`. `includes/Plugin.php:82`, `includes/Plugin.php:466-507`
- **Reload:** unpaid orders with checkout ID emit resume/auth attributes. Checkoutless ambiguous creates instead recover through a subsequent create replay with the saved request. `includes/Gateway.php:867-885`, `includes/AjaxHandler.php:94-119`
- **Square POS-app alternative:** callback stores `_sqtwc_pos_transaction_id`, `_sqtwc_payment_ids`; claims transaction globally using non-autoload option `sqtwc_pos_txn_<md5(transaction_id)>=order_id`, alongside duplicate-order lookup and per-order lock. Currency/location must match. Partial → on-hold; sufficient verified amount → note + `payment_complete()`. Offline client-only response stores `_sqtwc_pos_client_transaction_id` and manual-verification note, without marking paid. `includes/PosCallbackHandler.php:89-99`, `includes/PosCallbackHandler.php:110-180`, `includes/PosCallbackHandler.php:206-219`
- **Refund: ABSENT.** No refund method in the provider adapter; captured partial/duplicate payments produce Square Dashboard/manual-refund instructions instead. Attempt classes are `OrderMeta`, `CheckoutReconciler`, `OrderLock`, `PaymentSweeper`; no separate `Attempt` class. `includes/Services/SquareTerminalAdapter.php:23-159`, `includes/AjaxHandler.php:82-84`, `includes/Services/CheckoutReconciler.php:158-188`

## 12. Notable hardening and comments
1. Asset-loading predicates: “WCPOS checkouts … are not always is_checkout_pay_page().” Both checkout branches remain. `includes/Gateway.php:194-198`
2. Render-time order detection: WooCommerce may instantiate its gateway “before WordPress has parsed the order-pay query.” `includes/Gateway.php:149-155`
3. Indeterminate create: “Square may have created the checkout … Keep the attempt … same idempotency key.” `includes/AjaxHandler.php:145-149`
4. Cancel semantics: “cancel is a request, not a result.” `assets/js/payment.js:515-521`
5. Lock qualification: “The option driver is best-effort … MySQL GET_LOCK is the real mutual-exclusion guarantee.” `includes/Services/OrderLock.php:15-19`
6. Cross-order replay: order lock “cannot serialize two different orders replaying the same transaction”; `add_option()` supplies the global claim. `includes/PosCallbackHandler.php:206-219`
7. Scoped SDK HTTP discovery: “php-scoper rewrites those names … discovery finds nothing and every request throws before it is sent.” `includes/Services/SquareClientFactory.php:28-31`
8. Device identity distinction: monitoring `Device.id` “is NOT valid as a Terminal checkout device_id.” `includes/Services/SquareDeviceAdapter.php:103-117`
9. Lost diagnostic detail: error taxonomy fields “collide with the 'code' needle … to redact Terminal pairing codes”; mapper aliases `error_code`. `includes/Logger.php:30-38`, `includes/Services/SquareErrorMapper.php:127-129`
10. Webhook URL: asking merchants to retype it “only creates a way to get it wrong … Square signs over the notification URL.” `includes/Settings.php:158-162`
11. Health attribution: a delivery under previous settings “would mask exactly the broken setup this row exists to reveal.” `includes/WebhookHandler.php:98-105`
12. Unsaved Connect choice: otherwise a merchant choosing Production “would silently authorize the sandbox application”; environment/device choice are carried and persisted. `includes/Plugin.php:193-213`
13. OAuth disconnect race: cached generation could recreate a connection “moments after the administrator removed it.” `includes/Services/SquareOAuth.php:381-395`
14. Framed app launch: external protocol launch from an iframe is “dropped with no error”; navigation targets reachable top frame or `_top` anchor. `assets/js/payment.js:131-155`
15. WooCommerce submit button: it is “a decoy that reloads the page and wipes the status”; hidden only while this gateway is selected. `assets/js/payment.js:41-50`
