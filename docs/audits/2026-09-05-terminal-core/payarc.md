## 4. Payment lifecycle on the server
- Shape: `PayArcPaymentService` accepts injectable `Settings`, client, `TerminalService`, reconciler and clock. Public operations take an order-like object and return arrays. The related classes are **`PaymentAttempt`**, **`PaymentLock`**, **`PaymentReconciler`**. (`includes/Services/PayArcPaymentService.php:15-45`, `includes/Services/PayArcPaymentService.php:53`, `includes/Services/PayArcPaymentService.php:143`, `includes/Services/PayArcPaymentService.php:216`)
- **Start:** `start_payment_for_order(order,terminal_id='')` returns `already_paid` for paid orders; under `terminal` lock, returns `existing_attempt` for an identified in-flight attempt. Otherwise validates terminal, builds amount/payload and generates attempt UUID, provider transaction ID and separate idempotency UUID. (`includes/Services/PayArcPaymentService.php:53-95`)
- Before sale, only the in-flight option index is marked. After successful API response, `record_new()` stores `{attempt_uuid,transaction_id,terminal_id,status:"created",sale_response:array,trace_id?:string}`. A thrown sale clears the index and rethrows. (`includes/Services/PayArcPaymentService.php:90-135`)
- Order storage: `_patwc_current_attempt` holds the associative attempt; `_patwc_attempt_history` appends initial attempt snapshots. Mirrored scalar keys: `_patwc_current_trace_id`, `_patwc_current_transaction_id`, `_patwc_current_status`, `_patwc_current_charge_id`, `_patwc_current_terminal_id`. Status updates change current data, not historical snapshots, and preserve existing identifiers against empty replacements. (`includes/PaymentAttempt.php:7-14`, `includes/PaymentAttempt.php:23-85`, `includes/PaymentAttempt.php:243-264`)
- **Poll:** `poll_order()` returns `pending_callback` when no trace exists; otherwise returns stored final state or fetches under `reconcile` lock. `_patwc_last_poll_at` stores integer timestamp; provider calls are throttled to at least two seconds apart. `TRANSACTION_NOT_FOUND` means keep polling; other exceptions propagate. (`includes/Services/PayArcPaymentService.php:17-19`, `includes/Services/PayArcPaymentService.php:143-208`, `includes/Services/PayArcPaymentService.php:342-360`)
- **Cancel:** `cancel_order_payment()` uses `terminal` lock. Missing trace gives `not_cancelable_without_trace`, still polling; finalized attempts return current state. It cancels the attempt’s terminal, falling back to the configured default; stores `cancel_requested` plus `continue_polling:true`. “Already processed/cannot cancel” errors trigger authoritative lookup/reconciliation under `reconcile` lock. (`includes/Services/PayArcPaymentService.php:216-270`, `includes/Services/PayArcPaymentService.php:456-469`)
- **Webhook:** locate by callback `metadata.order_id`, then current trace meta, then current transaction meta. Missing trace returns 202 without reconciliation. With trace, acquire `reconcile` lock, refetch provider transaction, then call `PaymentReconciler::reconcile(order,payload,'webhook')`; callback claims alone do not complete payment. (`includes/WebhookHandler.php:115-160`, `includes/WebhookHandler.php:237-300`)
- **Reconcile:** identity accepts matching metadata order ID first, otherwise matching current trace or transaction ID. A paid order with conflicting identifiers returns conflict. Successful transactions must match order currency and exact minor-unit total. (`includes/PaymentReconciler.php:39-82`, `includes/PaymentReconciler.php:217-276`)
- Additional scalar/string meta: `_patwc_charge_id`, `_patwc_card_brand`, `_patwc_card_entry_mode`, `_patwc_card_last4`, `_patwc_processor_response_code`, `_patwc_processor_response_text`; `_patwc_verification_failure` stores an explanatory string. (`includes/PaymentReconciler.php:10-16`, `includes/PaymentReconciler.php:353-365`, `includes/PaymentReconciler.php:454-456`)
- Final callback dedupe: `_patwc_processed_callbacks` is an array of **`<trace-or-transaction>|<normalized-status>`** strings; duplicate returns `idempotent`, `continue_polling:false`. Final status notes and verification/conflict notes are written. (`includes/PaymentReconciler.php:47-63`, `includes/PaymentReconciler.php:95-108`, `includes/PaymentReconciler.php:368-391`)
- Paid transition: only sources `webhook`, `poll`, `cancel_lookup` can call `$order->payment_complete(chargeId ?: traceId ?: transactionId)`, and only if not already paid. No explicit WooCommerce failed/cancelled status transition is applied by these branches. (`includes/PaymentReconciler.php:88-108`, `includes/PaymentReconciler.php:430-445`)
- Locks: non-autoload options **`patwc_lock_<orderId>_terminal`** and **`patwc_lock_<orderId>_reconcile`**, payload `{expires_at:unixTime}`, 30-second expiry; `add_option`, stale delete/re-add, `finally` release; process-local array fallback without WP. Lock contention returns `{status:"conflict",message,continue_polling:true}`. The class explicitly calls this advisory. (`includes/PaymentLock.php:5-14`, `includes/PaymentLock.php:22-100`)
- Provider idempotency: UUID sent as `X-Idempotency-Key`, including generated keys for GET; credential retries reuse request arguments/key. No order-meta idempotency-key field is stored. Transaction ID is a deterministic 16-character `P`/base36-order/hash construction from the attempt UUID. (`includes/Services/PayArcClient.php:99-131`, `includes/Services/PayArcPaymentService.php:71-95`, `includes/Utils/PayArcIds.php:11-54`)
- Cleanup: cron/sweeper **ABSENT**. Option **`patwc_payarc_in_flight_attempts`** maps order IDs to `{status,trace_id,transaction_id,updated_at}`; lazy checking prunes entries older than 1,800 seconds or no longer in-flight. This removes index entries, not stored order attempts; lock expiry is also handled lazily. (`includes/PaymentAttempt.php:15-16`, `includes/PaymentAttempt.php:127-171`, `includes/PaymentAttempt.php:196-224`, `includes/PaymentLock.php:67-72`)
- Resume: stored current attempt makes another Start return `existing_attempt`, followed by polling; there is no page-load resume action. Refund: **ABSENT**; gateway advertises only `products`, and provider client exposes sale/get/cancel. (`includes/Services/PayArcPaymentService.php:59-65`, `assets/js/payment.js:246-265`, `assets/js/payment.js:305-330`, `includes/Gateway.php:13`, `includes/Services/PayArcClient.php:34-74`)

## 8. Money / currency handling
- `Utils\Money::to_minor_units(amount,currency): int`: precision map **USD/CAD/GBP/EUR=2, JPY=0**; unsupported currencies throw. Rejects negative amounts, excess fractional digits, fractional JPY, invalid numeric strings and integer overflow. No currency rounding is performed. (`includes/Utils/Money.php:12-56`, `includes/Utils/Money.php:83-97`, `includes/Utils/Money.php:112-133`)
- Finite float inputs are first formatted with `sprintf('%.10F')` and trailing zeros removed; strings use decimal concatenation, not floating-point multiplication. (`includes/Utils/Money.php:38-56`, `includes/Utils/Money.php:118-123`)
- `to_payarc_amount_object(amount,currency,tip=0,tax=0)` returns `{total,subtotal,currency,tip,tax}`, integer minor amounts with checked addition. Start passes WC order total/currency, leaving tip/tax zero. (`includes/Utils/Money.php:63-79`, `includes/Utils/Money.php:100-106`, `includes/Services/PayArcPaymentService.php:74-81`)
- Reconciler requires matching currency and exact integer minor units, preferring `amount.approved`, then `amount.total`, then scalar `amount`; accepts nonnegative integers or bounded digit strings, not floats. This is a local precision/verification map, not an API-discovered provider currency allowlist. (`includes/PaymentReconciler.php:253-336`, `includes/Utils/Money.php:12-28`)

## 11. Plugin-specific (must stay local)

## 12. Notable hardening and comments
1. “WooCommerce POS renders order-pay under the customer's user context”; the cashier’s nonce consequently differs, motivating the signed order token. (`includes/AjaxHandler.php:203-209`)
2. Denial logging explains that this failure was “invisible in merchant logs” without a server-side trace. (`includes/AjaxHandler.php:497-500`)
3. The lock “is not a database-atomic mutex” and does not guarantee exclusive critical-section entry. (`includes/PaymentLock.php:5-10`)
4. Live production V3 “rejects the curvpos Login AccessToken”; the documented default is therefore merchant SecretKey. (`includes/Settings.php:144-146`)
5. V3 requires `X-Idempotency-Key` “including GETs”; omission was observed returning 400. (`includes/Services/PayArcClient.php:105-106`)
6. An accepted sale can return `TRANSACTION_NOT_FOUND` “for several seconds”; polling treats this as waiting. (`includes/Services/PayArcPaymentService.php:191-194`)
7. `aborted` is documented as PayArc’s final cancelled-terminal state, observed after POST cancel. (`includes/PaymentAttempt.php:122-124`)
8. Failure detail exists so “a processor decline is distinguishable from a config problem”; regression commentary records three production declines previously logging only “decline”. (`includes/PaymentReconciler.php:112-114`, `tests/regression/reconciler-callbacks.php:409-411`)
9. Identifier-less registry duplicates otherwise “alarm[] the merchant about a device that is fully configured”; device identity takes priority over shared display names. (`includes/Services/PayArcConnectionService.php:443-455`)
10. Registry `pos_identifier` absence “must not read as a provisioning fault”; the comment distinguishes reporting metadata from the sale’s terminal serial. (`includes/Services/PayArcConnectionService.php:652-656`)
11. Callback secret is “Generated once and kept stable across reconnects”; `secret_token()` avoids `wp_generate_uuid4()` because the comment identifies its core implementation as mt_rand-backed. (`includes/Services/PayArcConnectionService.php:95-99`, `includes/Utils/PayArcIds.php:26-33`)
12. Settings-preservation regression explains that routine saving otherwise wipes the callback URL token—“callbacks then 401”—and learned V3 credential. (`tests/regression/gateway-ui.php:424-426`)
13. Logger distinguishes trusted prose from untrusted provider text, accepting over-redaction for whitespace-separated secrets while avoiding mangling “the key rotated”. (`includes/Logger.php:58-66`, `includes/Logger.php:181-186`)
